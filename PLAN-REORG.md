**Карта жёстких путей (главный вход для фазы реструктуризации):**
- Кодом из корня читается/пишется ровно один md — `GLOSSARY.md`
  (`tools/gen_glossary.py:25`, гейт `glossary-gen`). Все остальные корневые
  md (отчёты, PLAYBOOK, STYLE, SCHEMA, HANDOFF) кодом не открываются —
  их переезд безопасен для конвейера, ломает только текстовые ссылки.
- Корневые yaml (`taxonomy/topics/sources/glossary/labs`) захардкожены
  в 7 скриптах через `ROOT = Path(__file__).parent.parent` — двигать их
  можно только с правкой скриптов или после введения единого модуля путей.
- `taxonomy.yaml` (поля `dir: stage-N`) и `labs.yaml` (поля `path: pilot/lab/…`)
  ссылаются на каталоги — переименование `content/stage-N/` или `pilot/`
  требует синхронной правки данных.
- HANDOFF.md содержит 400+ ссылок голыми именами на корневые отчёты —
  при переезде отчётов потребуют массовой правки (грепаются однозначно).

## Фаза 1. Полномасштабный аудит (основная исследовательская фаза)

Ресёрч уже проведён (практики аудита ИИ-контента: claim-extraction →
evidence → verdict; LangChain-модель «docs test themselves»; GitLab
docs-testing; Google timeless docs; git-age гейты свежести). Аудит строится
шестью слоями; каждый слой — отдельная волна с отчётом.

### 1.1. Аудит фактов (самый дорогой слой)
- Случайная выборка 10–15 тем (стратифицированно: по этапам и уровням
  L1/L2/L3). Методика уже опробована разведкой: 6 тем ≈ 1 час, сверка
  чисел, версий, команд, сносок с первоисточниками из `sources.yaml`
  (OWASP, WSTG, NIST, документация инструментов — не произвольный веб).
- Контрольный срез «нормативных чисел»: пороги KDF, TTL токенов, пороги
  блокировок — сверка каждого с первоисточником и занесение в реестр
  (основа матрицы согласованности, фаза 4).
- Каждая находка — с доказательством (URL, цитата), как в миссиях аудита
  источников. Классификация: фактическая ошибка / устарело / спорно.

### 1.2. Аудит кода в листингах
- Массовая синтаксическая проверка всех 628 блоков: `compile()` для
  Python, `node --check` для JS, `bash -n` для bash, `yaml.safe_load`
  для yaml, `semgrep --validate` для правил. (Скрипт разведки уже это
  делает — формализовать.)
- Разметка договора «самодостаточный листинг vs фрагмент»: 10 известных
  фрагментов получают явный маркер, остальные обязаны компилироваться.
- Семантическая выборка: 5–10 атак из листингов воспроизвести руками
  (пересечение с лабами — там это уже детерминировано).

### 1.3. Аудит лаб и semgrep-правил
- Прогон всех 29 лаб по критерию приёмки (hack=1/tests=0 на `code.py`,
  hack=0/tests=0 на `solution.py`) и всех 19 правил через
  `pilot/semgrep/check.py`. Сличение фактических дат прогонов
  с `checked:` в `labs.yaml`.
- Разбор сирот: `pilot/lab/code.py` (оформить лабой или удалить),
  дубли `sast-principles/code` ≡ `semgrep-rules/code`,
  `postmessage-no-origin-check.ts`.

### 1.4. Аудит источников и ссылок
- Политика свежести: `volatility → макс. возраст checked`
  (fast ~1 мес., medium ~6 мес., stable ~12 мес.); отчёт о нарушителях.
- Выборочное повторное открытие 20–30 случайных URL (протокол
  «checked = реально открыт»), 4 записи `needs_manual_check`.
- `make links --external` полным прогоном (вне гейта, как задумано).

### 1.5. Аудит согласованности корпуса
- Перекрёстная сверка рекомендаций: SameSite по умолчанию, сроки жизни
  токенов, длины паролей, пороги блокировок — все упоминания по корпусу
  против реестра нормативных чисел из 1.1.
- Покрытие глоссария: частотный анализ жаргона этапов 2–3 (SBOM, CVSS,
  CVE/CWE, EPSS/KEV, SAST/DAST, OAuth/OIDC, IDOR/BOLA/BFLA…), список
  кандидатов в `glossary.yaml`.
- Нормы объёма: полная сверка `wordcount.py` по уровням (известный кейс:
  `app-architecture.md` 1813 слов прозы при норме 800–1700) — список
  нарушителей с вердиктом «править текст / править норму / исключение».

### 1.6. Аудит документации и процесса
- Рассинхрон чисел: SCHEMA.md, INFRA.md, STYLE.md, STATUS.md —
  «двенадцать тем» → 134, 301 источник → 351 и т.д. Полный список
  устаревших утверждений (правка — в фазе 2 или 4, здесь только реестр).
- Застоявшиеся хвосты: неутверждённые правила Н-11/У-2, открытые долги
  из STAGE*-отчётов, незакрытый отчёт `INTROS-INTROS_S1_02.md`
  (миссия `intros-s1-02` заблокирована оператором — не трогаем,
  только фиксируем).

Критерий приёма: отчёт `AUDIT-2026.md` с реестром находок (id, слой,
путь:строка, доказательство, вердикт, предложение), каждая находка
воспроизводима. Маркер: `АУДИТ 2026 ЗАВЕРШЁН`.

## Фаза 2. Реструктуризация репозитория

Ресёрч проведён (kubernetes/website, OWASP CheatSheetSeries, rust-lang/book,
ADR-конвенция Нюгарда, git rename detection, trunk-based). Ключевые правила,
принятые из ресёрча:

- **Переезд только `git mv`, отдельным коммитом от правок содержимого**
  (100% similarity → `git log --follow` работает гарантированно).
- **Мелкие партии, каждый коммит зелёный** (`make check` после каждого).
- Коммиты прямо в `main` (trunk-based), без долгоживущих веток.
- **URL сайта не меняются вообще** — `content/stage-N/` и навигация
  остаются как есть; реструктуризация касается только корня и служебных
  каталогов. Редиректы не нужны, потому что публичные страницы не двигаются.

### Целевая структура (предложение)

```
/                       ← только «контрактные» файлы
  README.md             ← новый: карта структуры за один экран
  Makefile, mkdocs.yml, .gitignore
  HANDOFF.md            ← живая точка входа оркестратора (остаётся)
  PLAYBOOK.md, SCOPE.md, SCHEMA.md, STYLE.md   ← действующие нормы
  *.yaml                ← реестры (не двигаем: захардкожены в 7 скриптах)
content/ sources/ templates/ research/ tools/ pilot/ .github/
docs/
  adr/0001-repo-layout.md
  reports/              ← живые отчёты о состоянии (INFRA, PAGES, PILOT*)
journal/                ← архив снимков миссий (только чтение)
  2026-08-write-0.md … (переименование в датированную схему — опционально)
```

Явно **не** делаем: переименование `content/stage-N/` (ломает
`taxonomy.yaml`, сборку, исключения), переезд корневых yaml (ломает 7
скриптов), Diátaxis-перекройку content (проект уже типизирован уровнями
L1–L3 и режимами; реорганизация ради реорганизации).

### Шаги

1. **Единый модуль путей**: `tools/paths.py` (ROOT, CONTENT_DIR, реестры,
   GLOSSARY_MD…), перевод скриптов на него. Заодно устранение
   cwd-зависимости (`mdtext.py:130`, `linkcheck.py:56`,
   `lint_selftest.py`) — все пути от ROOT. Отдельный коммит, `make check`
   зелёный.
2. **Внешний план в переменную окружения**: `PLAN_PATH` из env
   (`APPSEC_PLAN_PATH`) с текущим значением как дефолтом — снимает
   зависимость от конкретной машины, поведение «ПРОПУЩЕНО» сохраняется.
3. **Переезд снимков миссий в `journal/`** партиями: WRITE-*,
   STAGE*-*, INTROS-*, FINAL-CHECK, GAP-FIX, WARNINGS, CLEAN-HEADERS,
   STATUS, WRITING-PLAN, SOURCES. Каждая партия — коммит чистого `git mv`.
4. **Переезд живых отчётов в `docs/reports/`**: INFRA.md, PAGES.md,
   PILOT.md, PILOT-AUTH.md (с обновлением чисел — отдельным коммитом
   после переезда).
5. **Правка текстовых ссылок** (отдельные коммиты после каждого переезда):
   HANDOFF.md (400+ упоминаний голыми именами — массовая замена по
   грепабельным именам), docstring'и в tools/*.py, `link:` в 19 правилах
   Vale, комментарии в yaml и mkdocs.yml.
6. **README.md** — карта новой структуры: каталог → назначение, команды,
   ссылка на ADR.
7. **Контроль**: `make check`, `make lint-selftest`, `make site`,
   `make check-site`, финальный grep-аудит остаточных ссылок на старые
   пути (`grep -rn 'STAGE1-\|WRITE-\|INTROS-' tools/ *.yml` → пусто или
   осознанные исключения), `git log --follow` по 2–3 переехавшим файлам.

Риски и ответы:
- `.smgr/*/status.json` и `~/.supermanager/missions/*/dossier.md` ссылаются
  на старые пути текстом — не ломаются (вне git), но оркестратору при
  возобновлении миссий нужна актуальная карта: верхний раздел HANDOFF.md
  после реструктуризации обязан её содержать.
- HANDOFF.md — живой журнал; его массовая правка ссылок — единственная
  правка «истории», на которую идём осознанно (исторические записи
  останутся валидны по смыслу: ссылка ведёт на новое место того же файла).

Критерий приёма: корень из ≤15 файлов, все гейты зелёные, история
переехавших файлов читается через `--follow`, README описывает фактическую
структуру. Отчёт `docs/reports/REORG-2026.md`. Маркер: `РЕСТРУКТУРИЗАЦИЯ
СДАНА`.

## Фаза 4. Укрепление конвейера (закрытие слепых зон, найденных аудитом)

Каждый пункт — по результатам фазы 1; без этой фазы аудит останется
разовой акцией.

1. **Дрейф-гейт производных**: `gen_sources_md.py --check` в `make check`
   (находка П3 воспроизводится в один прогон).
2. **Компиляция листингов**: новый линтер `tools/lint_code.py`
   (Python/JS/bash/yaml/semgrep-validate), договор о маркере фрагментов,
   правило `C-CODE-*` + фикстуры в `lint_selftest.py`.
3. **Прогон лаб и правил в CI**: неблокирующая джоба → блокирующая;
   расхождение `labs.yaml.checked` с фактом — warning.
4. **Глоссарий этапов 2–3**: пополнение `glossary.yaml` по списку из 1.5;
   правило «частотный термин вне глоссария» как warning (порог для
   `G-NEW-PAGE`).
5. **Политика свежести источников**: правило `volatility → возраст
   checked` в `validate.py`; quarterly-ритуал повторного открытия
   выборки.
6. **Timeless-стоп-слова** (практика Google): «сейчас», «на данный
   момент», «новый», «актуальный», «недавно» — в `stoplist.py` как
   предупреждения.
7. **Матрица нормативных чисел** и статусная модель (критерии выхода
   из `draft`) — по итогам 1.1/1.5, правки в PLAYBOOK/SCHEMA отдельным
   решением оператора.
8. **Обновление рассинхронированных чисел** в SCHEMA/INFRA/STYLE/STATUS
   по реестру из 1.6.

Критерий приёма: `make check` покрывает бывшие слепые зоны, новые
правила имеют фикстуры, CI прогоняет лабы. Маркер: `КОНВЕЙЕР УКРЕПЛЁН`.

5. **Глубина фазы 4**: всё найденное (пп. 1–8).
6. **Git**: коммиты в `main` по ходу работ разрешены. Push в origin —
   отдельным решением, как принято в проекте.
