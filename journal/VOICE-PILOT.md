# Пилот новой схемы введений (VOICE-PILOT)

Дата: 2026-08-30. По плану `PLAN-VOICE.md`, фаза 0.

## Устройство

Шесть тем разного профиля (sqli-basics L1, password-storage L1, idor L2,
trivy L2-инструмент, quality-gates L1 этапа 3, security-headers L2/L3).
Для каждой написан новый вариант введения по решениям оператора
(пример/поломка раньше определения, без фиксированных меток, свободная
форма, неравномерный ритм, конкретный артефакт в первых 250 словах,
стоп-лист штампов корпуса). Оператору предъявлены слепые пары
«текущее/новое» с перемешанными номерами (`.review/voice/`, ключ — после
выбора; папка вне git).

## Исход выборки

| Тема | Победитель | Примечание |
|---|---|---|
| password-storage | новый | старого введения не было (стаб) |
| trivy | новый | старого не было |
| quality-gates | новый | старого не было |
| idor | старый | честное сравнение: старое полноценное введение (Анна, счёт 1001) |
| security-headers | старый | честное сравнение |
| sqli-basics | новый | старого не было |

Промежуточный факт: в честных сравнениях победили старые введения —
то есть хорошо исполненная действующая схема оператору нравится.
**Итоговое решение оператора: стандартом становится всё же новая схема**
(пример первым, меток нет), пилот признан состоявшимся; новые варианты
sqli-basics, password-storage, trivy, quality-gates — утверждённые
образцы. Темы idor и security-headers не трогаем: они уже имеют сильные
введения, переписывание под новую схему — отдельной волной и не в
первую очередь.

## Что утверждено образцами (для фазы 1)

- Поломка/артефакт в первых 50–100 словах (дамп-строка MD5, чужой счёт
  по invoice_id, зелёный пайплайн с упавшим сканером, строка вывода
  trivy с CVE-2021-44228).
- Определение и термин — после примера, на месте, без жирных меток.
- Крючок от опыта — только на L1 и только честный (у L2/L3 — свободный
  вход: задача, контракт, сценарий).
- Финал введения — словесный анонс разбора без номеров блоков.
- Длины: L1 ~210–240 слов, L2 ~170–200, сжатое ~120.
