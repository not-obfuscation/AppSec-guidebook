## 0. Коротко

Кроме политики безопасности содержимого, браузер понимает ещё несколько полей
ответа, каждое из которых включает одно небольшое ограничение. Читать эту
группу надо с обратным ожиданием: она **сокращается**. Часть полей вытеснена
директивами CSP, часть признана вредной, часть мертва. Единственное, у
которого есть собственная спецификация и собственная модель угроз, — HSTS.

**Зачем это в работе AppSec-инженера.** Отчёт сканера про «отсутствующие
security-заголовки» приходит почти на каждый сервис, и половина его пунктов
устарела. Разбирать такой отчёт значит знать, какие поля ещё работают.

## 3. Механика

`X-Content-Type-Options: nosniff` запрещает браузеру угадывать тип
содержимого вместо объявленного в `Content-Type`. Cheat Sheet называет
последствие угадывания прямо: неисполняемый тип превращается в исполняемый.

`Referrer-Policy` управляет тем, сколько сведений об адресе страницы уйдёт в
поле `Referer` следующего запроса. Рекомендация Cheat Sheet —
`strict-origin-when-cross-origin`; ASVS v5.0-3.4.5 требует политики,
предотвращающей утечку пути и строки запроса третьим сторонам.

`X-Frame-Options` запрещает встраивание страницы в кадр. Cheat Sheet пишет,
что директива `frame-ancestors` политики CSP вытесняет это поле в браузерах,
которые её поддерживают, и что само поле бесполезно там, где взаимодействовать
не с чем: у ответа с перенаправлением или у API, отдающего JSON. То же говорит
ASVS v5.0-3.4.6, называя поле устаревшим.

Рядом два поля, которые надо не настраивать, а убирать: `X-XSS-Protection`
Cheat Sheet советует не задавать вовсе либо явно выключать (`0`), потому что
в отдельных случаях оно само создаёт уязвимость; `Expect-CT` помечен как
неиспользуемый.

**HSTS** устроен иначе — у него есть RFC 6797. Директива `max-age` объявлена
обязательной, `includeSubDomains` — необязательной и не имеющей значения.
Значение `max-age=0` заставляет браузер забыть политику, и присутствие
`includeSubDomains` при нулевом сроке игнорируется. Три требования уровня MUST
определяют границы механизма: узел **не должен** присылать это поле в ответе
по незащищённому транспорту; браузер **обязан** игнорировать поле, полученное
по незащищённому транспорту; браузер **обязан** игнорировать `http-equiv` с
этим именем в разметке. При обращении к уже известному узлу браузер **обязан**
разорвать соединение при любой ошибке транспорта — включая ошибки проверки
сертификата (§ 8.4).

Свой минимальный пример — четыре поля в одном ответе:

```http
HTTP/1.1 200 OK
Content-Type: text/html; charset=UTF-8
Strict-Transport-Security: max-age=63072000; includeSubDomains
X-Content-Type-Options: nosniff
Referrer-Policy: strict-origin-when-cross-origin
```

Чего здесь нет: `X-Frame-Options`, потому что встраивание закрывает
`frame-ancestors 'none'` из политики CSP, и `X-XSS-Protection`, потому что его
рекомендуют не задавать.

**Окно, которое HSTS не закрывает.** RFC 6797 § 14.6 называет его bootstrap
MITM: первое обращение к незнакомому узлу по адресу со схемой `http` идёт по
незащищённому каналу, и политики у браузера ещё нет. Отсюда третья директива в
рекомендации Cheat Sheet — `preload`: она относится не к протоколу, а к
спискам, встроенным в браузеры.
