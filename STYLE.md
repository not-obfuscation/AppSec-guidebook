# Свод языка: часть 6 `PLAYBOOK.md`, разложенная на проверки

Правила языка живут в части 6 `PLAYBOOK.md`. Этот документ их не переписывает,
не дополняет и не отменяет. Он делает с ними три вещи:

1. присваивает каждому проверяемому пункту идентификатор, на который ссылается
   вывод инструмента;
2. называет для каждого идентификатора точную машинную формулировку — то, до
   чего правило сжимается в регулярном выражении, вместе с ценой этого сжатия;
3. перечисляет пункты, которые машине не сдаются, чтобы ревизия глазами шла по
   списку, а не по памяти (§ 9).

Если формулировка в этом документе расходится с частью 6, права часть 6, а
расхождение — дефект обвязки.

Сам этот файл проверками не покрыт: он обязан цитировать запрещённые
конструкции, чтобы их определить, и на первом же правиле дал бы двадцать
срабатываний на себя. Глоб проверок ограничен `content/**/*.md`.

## 1. Как устроены проверки

### 1.1 Три уровня, а не два

| Уровень | Что значит | Что делает `make check` |
|---|---|---|
| `error` | Нарушение, у которого нет законного прочтения | печатает и возвращает ненулевой код |
| `warning` | Признак нарушения; бывают законные исключения | печатает, код возврата не меняет |
| глазами | Правило есть, машинного признака нет | не печатает ничего, живёт в § 9 |

Уровень назначается по одному вопросу: **бывает ли у этого срабатывания
законное прочтение?** Если бывает и не единожды — правило warning, иначе error.
Проверено это не рассуждением, а прогоном по двенадцати готовым темам: правило,
давшее хотя бы одно законное срабатывание, до error не поднимается, пока
формулировка не сузится. Двенадцать тем — маленькая выборка, поэтому уровень
правила не окончателен: правило, начавшее шуметь на новых темах, сужается или
опускается в warning, и причина пишется рядом с ним в конфиге.

Правило, которое шумит, обучает автора пролистывать вывод. Обвязка, вывод
которой пролистывают, не работает, даже когда каждая её проверка технически
исправна. Поэтому сужение правила до нуля ложных срабатываний считается здесь
не смягчением требования, а условием того, что требование вообще исполняется.

### 1.2 Семейства идентификаторов

| Семейство | Инструмент | Конфиг |
|---|---|---|
| `L-*` | Vale — язык и типографика прозы | `tools/vale/.vale.ini`, `tools/vale/styles/AppSec/*.yml` |
| `MD*` | markdownlint-cli2 — разметка | `tools/markdownlint.jsonc` |
| `S-*` | свои проверки свода — то, чего нет ни в Vale, ни в markdownlint | `tools/lint_style.py`, `tools/linkcheck.py` |
| `G-*` | глоссарий | `tools/glossary_lint.py`, `glossary.yaml` |
| `C-*` | контентная модель и frontmatter | `tools/validate_content.py`, `tools/wordcount.py` (объём), `SCHEMA.md` |

`MD*` — родные номера markdownlint, чтобы не заводить второе имя тому, у чего
имя уже есть. Остальные три семейства именует этот свод.

### 1.3 Что во что не лезет

Разделение обязанностей между инструментами выбрано так, чтобы одно нарушение
печаталось один раз:

- **Vale** видит только прозу. Он сам пропускает содержимое ограждённых блоков
  и инлайновый код, поэтому `if (!stored)` не считается восклицательным знаком,
  а `data` внутри обратных кавычек — канцеляритом. Это причина, по которой
  запрещённые конструкции проверяет Vale, а не `grep` по тексту: `grep` этого
  различения не делает, и его вывод приходится читать с оговоркой «а это код».
- **markdownlint** видит только разметку: заголовки, списки, ограждения,
  пробелы. Ни одного правила о смысле слов ему не поручено.
- **Свои проверки** берут то, что не умеет ни тот, ни другой: длину строки
  внутри листинга, порядок номеров в списке, продолжающем выноски, границу
  между кодом и знаком препинания.
- **Глоссарий** берёт всё, что требует знания списка терминов, — потому что
  список должен быть один, и он в `glossary.yaml`.

Из этого правила есть два следствия, оба зафиксированы в конфиге markdownlint
с указанием причины: `MD044` (написание имён) выключено в пользу `G-CANON`,
`MD013` (длина строки) — в пользу `S-CODE-WIDTH`, который меряет длину там, где
свод её ограничивает, и не меряет там, где не ограничивает.

### 1.4 Исключения

Часть срабатываний законна навсегда, а не до правки. Термин спецификации,
процитированный дословно, остаётся термином спецификации при любой редактуре
абзаца. Такие срабатывания снимаются файлом `tools/exceptions.yaml`:

```yaml
- rule: AppSec.Banned      # идентификатор правила как его печатает инструмент
  file: content/stage-0/cors.md
  match: "простой"         # подстрока найденного, а не строка файла
  reason: >
    «Простой запрос» — термин Fetch Standard (simple request), а не оценка
    сложности. Употреблён как термин, с раскрытием при первом появлении.
  added: 2026-08-22
```

Четыре условия, без которых исключение не заводится:

1. **Причина текстом.** Не «ложное срабатывание», а почему прочтение законно.
2. **Адрес.** Файл и подстрока. Исключение «правило X выключено везде» — это не
   исключение, а отмена правила, и делается в конфиге правила.
3. **Дата.** Чтобы при ревизии было видно, сколько исключение живёт.
4. **Исключение — не способ закрыть замечание.** Замечание к содержанию
   закрывается правкой содержания. Исключение закрывает только те случаи, где
   правило неприменимо в принципе.

Фильтр применяется обёрткой `tools/check.py` единообразно ко всем четырём
инструментам, а не средствами каждого: у Vale, markdownlint и своих скриптов
механизмы исключений разные и несовместимые, а список исключений должен
читаться в одном месте. Снятые исключениями срабатывания обёртка печатает
отдельным разделом и считает — молча спрятанное исключение через полгода
неотличимо от отсутствующей проверки.

## 3. Обращение, тон, время, залог — 6.1

### L-ADDRESS { #L-ADDRESS }

**Свод:** «вы» со строчной, повелительное наклонение множественного числа; «ты»
не используется; заглавная «Вы» запрещена (6.5).

**Машина:** два выражения. Первое — любая форма «ты» (`ты`, `тебе`, `тебя`,
`тобой`, `твой` и словоформы). Второе — формы «вы» с прописной, но **только
после строчной буквы или знака препинания**: `Вы` в начале предложения
неотличимо от корректного «Вы» после точки, а «Вы» посреди фразы отличимо.

**Цена:** «Ваш стенд» первым словом абзаца правило пропустит. Это осознанный
обмен: без ограничения слева правило ловило каждое законное «Вы» в начале
предложения, а таких в двенадцати темах больше, чем нарушений.

**Что осталось глазами:** повелительное наклонение, «мы» только в практических
разделах, «я» только в авторских врезках. Морфологии у Vale нет, а без неё
наклонение не отличить от изъявительного.

### Тон

Проверяемых признаков у тона два, и оба уже заведены: `L-EMOJI` (восклицательные
знаки и эмодзи) и `L-EVAL` (оценка без факта). Всё остальное — снисходительность,
бравада, юмор ради юмора, запугивание, «хакерская» романтика — машине не сдаётся
и живёт в § 9.

### Время и залог

Не проверяются. Настоящее время и активный залог требуют морфологического
разбора; ни у Vale, ни у обвязки его нет. Пассив, кроме того, разрешён сводом в
трёх случаях, и признака, отличающего разрешённый пассив от лишнего, у машины
нет тем более. § 9.

### S-SENT-LONG { #S-SENT-LONG }

**Свод:** предложение 7–15 слов, свыше 25 переписывается.

**Машина:** текст режется на предложения по `.`, `!`, `?` с пропуском
сокращений свода (`т. е.`, `т. д.`, `т. п.`, `§`, `рис.`, номера версий вида
`v5.0-3.4.4`, `RFC 9110 § 9.2.1`), слова считаются пробелами. Слово — то, в чём
есть буква, цифра или обратная кавычка: моноширинный фрагмент словом считается
намеренно (он занимает место и требует чтения), а тире, знак параграфа и маркер
цитаты `>` — нет. Свыше 25 — предупреждение.

**Цена:** нижняя граница «7 слов» не проверяется — короткое предложение не
дефект, а признак; а верхняя проверяется как детектор выбросов, ровно в том
качестве, в котором её разрешает 6.7. Резать русский текст на предложения
регулярным выражением надёжно нельзя, поэтому правило — предупреждение
навсегда, до error не поднимается.

Тире словом не считается с 2026-08-24. До этого счёт шёл простым делением по
пробелам, и одиночное тире — знак, которого свод же и требует (`L-DASH`), —
прибавляло слово. На перечислении через тире («источник — путь — сток —
отсутствующий контроль») счёт завышался на три, и тринадцать предложений
корпуса объявлялись длинными за собственную пунктуацию.

### S-PARA-LONG { #S-PARA-LONG }

**Свод:** абзац 3–7 строк.

**Машина:** абзац свыше 100 слов — предупреждение.

**Цена:** «строка» в исходнике не равна строке на экране, а на экране зависит
от ширины окна и от шрифта читателя. Поэтому норма пересчитана в слова: 3–7
строк вёрстки — это примерно 40–90 слов, порог поставлен выше верхней границы,
чтобы правило ловило только настоящие простыни. Это замена метрики, а не
метрика свода, и потому предупреждение.

### S-HEAD-DEPTH { #S-HEAD-DEPTH }

**Свод (6.4):** не более 3 уровней заголовков.

**Машина:** заголовок `####` и глубже — ошибка. Иерархию без пропусков
(`H3` только после `H2`) проверяет `MD001`, один `h1` на страницу — `MD025` и
`MD041` с `front_matter_title: ""`: поле `title` во frontmatter заголовком
документа не считается, иначе заголовок темы объявляется вторым.

## 4. Хеджирование — 6.2

**Оговорки, ограничивающие область действия утверждения, не сокращаются
никогда.** Из этого следует требование к обвязке, а не к тексту:

> **Ни одно правило этого свода не помечает хеджирование.** Правило, которое
> пометило «обычно», «как правило», «при необходимости», «допускается»,
> «могут быть», «в большинстве случаев», «зачастую», «как минимум», «скорее
> всего», «по умолчанию», — дефект обвязки и правится в правиле, а не в тексте.

Это не оговорка на будущее, а причина, по которой в § 2 нет ни одного правила
семейства «вода», «канцелярит-как-в-Главреде» и «пустые слова», хотя такие
правила есть в каждом готовом стайлгайде Vale — и именно поэтому ни один
готовый стайлгайд здесь не подключён. `BasedOnStyles` в `.vale.ini` содержит
ровно `AppSec` и ничего больше.

Проверить это требование можно и машинно, на самой обвязке. Список модальных
слов свода прогоняется через все правила как текст: ни одно срабатывание —
условие приёмки обвязки, а не текста. Прогон — `tools/lint_selftest.py`.

Разведение обязательного и необязательного (ГОСТ Р 2.105-2019 п. 5.2.2: **должен
/ требуется / не допускается / запрещается** против **как правило / допускается
/ при необходимости / могут быть**) машина не проверяет: она не знает, какое из
двух значений автор имел в виду. § 9.

## 5. Терминология — 6.3

### L-LATIN { #L-LATIN }

**Свод:** аббревиатуры и названия продуктов — латиницей, без кавычек, без
склонения, без наращений; падеж решается дескриптором («не в API, а в
API-методе»).

**Машина:** три выражения на латинское слово с приклеенным русским окончанием —
через апостроф (`JWT'ом`, `JWT’ом`), через дефис (`JWT-ом`) и без разделителя
(`JWTом`). Окончания перечислены списком.

**Цена:** законные гибриды через дефис («`SQL`-инъекция», «`API`-ключ»,
«`CSRF`-токен») от `JWT-ом` отличаются тем, что после дефиса стоит корень, а не
окончание, — поэтому список окончаний закрытый и коротко проверяемый. Слово
после дефиса, которое одновременно является окончанием, правило пометит ложно;
таких в русском нет.

Отсутствие кавычек вокруг латиницы отдельным правилом не проверяется: `L-QUOTES`
запрещает прямые кавычки вообще, а «ёлочки» вокруг латиницы от «ёлочек» вокруг
цитаты машине неотличимы. § 9.

### G-CANON { #G-CANON }

**Свод:** один термин — одно написание на весь сайт; синонимы живут только в
глоссарии.

**Машина:** каждое слово прозы, совпадающее с каноническим написанием термина
или его синонимом **с точностью до регистра**, но не совпадающее буквально, —
ошибка с указанием канонической формы. Источник списка — `glossary.yaml`, тот
же, из которого собирается сам глоссарий: второго списка правильных написаний в
проекте нет.

**Дефис значим.** Сводить написания «с точностью до дефиса» правило не может: в
этой предметной области дефис несёт смысл. `SameSite` — атрибут cookie,
`same-site` — отношение двух сайтов из rfc6265bis, и оба написания стоят в одном
предложении темы `cookies` законно. То же у `__Secure-` (префикс имени) и
`Secure` (атрибут). Правило, слепое к дефису, объявило бы каждую такую пару
ошибкой — а таких пар в корпусе больше, чем настоящих расхождений в регистре.

**Область:** проза страницы, кроме чужих слов. Не проверяются:

* инлайновый код, ограждённые блоки, автоссылки и всё, что похоже на имя домена
  или путь. Это причина отказа от `MD044`: он ругался на `graphql.org` в блоке
  источников, требуя `GraphQL.org`;
* блок «Источники» целиком — он сплошь состоит из чужих заглавий
  («Cross-Origin Resource Sharing (CORS)», «Session ID Properties»,
  «Introspection»), а заглавие цитируется буквально (7.4);
* текст в «ёлочках» — цитата или чужое название: «Authentication Failures» как
  раздел учебного плана, «ЭКСПЛОЙТ НЕ СРАБОТАЛ» как вывод программы;
* пробег из двух и более латинских слов с прописной буквы — английское имя
  собственное: в `OWASP Session Management Cheat Sheet` слово `Session` не есть
  термин `session`, написанный не так.

Первое употребление в начале предложения записывается с прописной буквы, и это
законно: правило разрешает вариант, отличающийся от канонического только первой
буквой, если слово стоит в начале предложения. Началом предложения считается и
заголовок, и пункт нумерованного списка, и выделенный фрагмент, открывающий
абзац: «**Соль не удорожает перебор.**» — начало, а не слово посреди фразы.

### G-FIRST { #G-FIRST }

**Свод:** первое употребление в теме — «межсайтовый скриптинг (cross-site
scripting, XSS)» плюс ссылка на глоссарий; далее только `XSS`.

**Кого правило спрашивает.** Только аббревиатуры: латиница прописными от двух
букв, у которой в глоссарии есть расшифровка, — `HTTP`, `TLS`, `HSTS`, `CSPRNG`,
`MITM`. Читатель, встретивший `HSTS` без расшифровки, не может даже поискать её.
Русские слова, у которых в глоссарии заполнено только поле `en`, правило не
трогает: «метод (method)» в скобках — не раскрытие, а шум. Поле `en` заведено,
чтобы читатель нашёл англоязычную литературу, и обязательства на предложение оно
не накладывает.

**Машина:** первое вхождение термина в материале страницы признаётся раскрытым,
если выполнено любое из четырёх:

1. в том же предложении стоит английское раскрытие термина из `glossary.yaml`;
2. в том же предложении стоит и полная русская форма (термин или русский
   синоним), и аббревиатура;
3. страница названа в поле `defines` записи глоссария — тема, которая термин
   вводит, раскрывает его собственным содержанием, а не скобками;
4. термин раскрыт в теме-предпосылке: какая-нибудь из страниц транзитивного
   замыкания поля `prerequisites` названа в `defines` этого термина. Порядок
   чтения гарантирует, что читатель уже встретил расшифровку, и требовать её
   второй раз — значит требовать шума. Это же делает поле `prerequisites`
   проверяемым по существу: девять предупреждений из двадцати четырёх снялись
   именно им, а оставшиеся — настоящие ссылки вперёд.

Иначе — предупреждение.

**Блоки 13 «Дальше» и 14 «Источники» из области правила исключены.** Они говорят
не о материале страницы, а о других страницах и чужих документах. Аббревиатура в
указателе «`tls-and-proxy` — почему `upgrade-insecure-requests` не заменяет
HSTS» — ссылка вперёд, а не первое употребление.

**Цена:** уровень warning, а не error, по двум причинам. Первая: двенадцать
готовых тем написаны до появления глоссария, и правило с уровнем error закрыло
бы `make check` на неделю авторской работы по содержанию. Вторая: правило судит
о раскрытии по форме, а раскрытие бывает и абзацем без скобок. Замечания
собираются в `INFRA.md` с разбивкой по темам и правятся автором в порядке
ревизии.

**Ссылка на глоссарий при первом употреблении** (6.3 и 11.2 п. 14) — задача
сборки, а не автора: движок ставит её сам, в исходнике темы её нет и быть не
должно. Поэтому в правилах её нет.

**Расшифровка аббревиатуры при наведении** — тоже задача сборки. Движок
подставляет на каждую страницу определения `*[HTTP]: Hypertext Transfer
Protocol` из `glossary.yaml` (расширение `abbr`), и браузер показывает
расшифровку по наведению на любое вхождение, а не только на первое. Это сильнее
скобок, и потому `G-FIRST` остаётся предупреждением: он говорит о тексте,
который читают с листа, а не о собранном сайте.

### G-SYNSET { #G-SYNSET }

Блокирующая проверка 9.4: два термина с пересекающимися синонимами.
Ошибка в самом глоссарии, не в темах, поэтому error.

### G-UNUSED { #G-UNUSED }

Предупреждающая проверка 9.4: термин без ссылающейся темы. Глоссарий
собирается из терминов, которыми темы уже пользуются, поэтому срабатывание
означает либо опечатку в написании, либо термин, заведённый впрок.

Поиск идёт по прозе **вместе с инлайновым кодом** и по всей странице, включая
блоки 13 и 14. Причина: имена заголовков и атрибутов 6.4 велит ставить в
обратные кавычки, и `Set-Cookie`, `HttpOnly`, `Vary`, `X-Forwarded-For` в чистой
прозе не встречаются вовсе. Правило снисходительное намеренно — ложное «термин
не нужен» дороже пропущенного.

Словоформы правило учитывает основой: русское слово усекается на два символа
(но не короче четырёх) и продолжается любыми буквами, поэтому «граница доверия»
находится в «за границей доверия». Морфологического разбора здесь нет и не
нужно: вопрос «употреблён ли термин вообще» такую грубость терпит, а вопрос «в
какой форме» этим инструментом не задаётся.

### G-NEW-PAGE { #G-NEW-PAGE }

Не правило, а метрика 6.7: число новых, ранее не определённых
терминов на страницу. Порога у неё нет и не будет — 6.7 запрещает пороги
читабельности, а этот счётчик стоит в тексте свода на их месте. Печатается
таблицей в отчёте, ничего не валит. Норму «не более трёх новых терминов в
абзаце» (6.6) счётчик не проверяет: «новый» здесь значит «ранее не
определённый», а определённость термина в абзаце выше машина не видит.

### Sentence case в заголовках

Не проверяется. Признак «Что Такое SQL-Инъекция» — прописная буква у слова
посреди заголовка, но в этом гайде посреди заголовка законно стоят `SPA`,
`REST`, `GraphQL`, `Argon2id`, `SameSite`, и правило поймало бы их все. § 9.

## 6. Типографика и листинги — 6.4, 7.1

### L-QUOTES { #L-QUOTES }

**Свод:** кавычки — «ёлочки», вложенные — „лапки“, внутри кода — прямые.

**Машина:** пара прямых двойных кавычек с содержимым до 80 символов в прозе.
Внутри кода Vale не смотрит, поэтому `"application/json"` в листинге законно.
Вложенные „лапки“ не проверяются: чтобы отличить пропущенную вложенность от
единственного уровня, нужно разбирать вложенность кавычек, а не искать образец.

### L-DASH { #L-DASH }

Дефис или два дефиса, окружённые пробелами: в этой позиции в русском
тексте стоит длинное тире. Дефис без пробелов правило не трогает, он законен.

### L-RANGE { #L-RANGE }

`2020-2024` и числовой диапазон с единицей (`7-15 слов`,
`20-30 %`): по своду диапазон пишется коротким тире без пробелов.

### L-PERCENT { #L-PERCENT }

Цифра, за которой сразу `%`. Первая версия правила искала
`\d\s*%` и помечала правильное `20 %` вместе с неправильным `20%`; исправлено
до `\d%`, проверено на строке с обоими написаниями.

### L-NBSP { #L-NBSP }

**Свод:** неразрывный пробел в «10 МБ», «§ 3», «т. е.», «CVE‑2021‑44228», перед
тире.

**Машина:** обычный пробел перед единицей измерения после числа, после `§`
перед цифрой, внутри `т. е.` / `т. д.` / `т. п.`.

**Цена:** уровень warning, и это самое многочисленное срабатывание в корпусе
(130 из 162). Причина — не спорность правила, а то, что неразрывный пробел
невидим: автор не вставляет его в потоке письма, и правка эта механическая, для
отдельного прохода. Единица измерения ищется по закрытому списку, поэтому
«10 попыток» правило не трогает. Слева от числа требуется не буква: иначе цифра
на конце имени продукта читается как величина с единицей, и «переход на IMDSv2 с
отключением» правило разбирает как «2 с» (находка Н-S4 миссии SSRF). Имена
такого вида в гайде обычны — `IMDSv2`, `HTTP2`, `SHA2`, `CSP3`. Неразрывный
пробел перед тире и внутри номеров
`CVE` не проверяется: в первом случае признак сливается с `L-DASH`, во втором
номер `CVE` в этом гайде всегда стоит внутри обратных кавычек, куда Vale не
смотрит.

### L-YO { #L-YO }

**Свод:** «ё» пишется всегда.

**Машина:** правило-подстановка с закрытым списком слов, у которых нет
омографа с «е»: «еще», «ее», «нее», «свое», «объем», «учет», «отчет», «счет»,
«идет», «придет», «дает» и словоформы. Каждое слово в списке проверено на
отсутствие второго чтения.

**Цена:** слова с омографами («все» / «всё», «небо» / «нёбо») в списке
отсутствуют — их правило пропустит. Полная проверка «ё» требует словаря с
морфологией и снятием омонимии; закрытый список даёт ноль ложных срабатываний
и ловит частотную часть. Расширять список можно только словом, у которого
второго чтения нет.

**Правка 2026-08-23 (миссия `appsec-stage1-a01`).** У слова «счёт» ударение в
множественном числе подвижное, и «ё» там исчезает: счета́, счето́в, счета́м,
счета́ми, счета́х. Запись `счет\p{L}*` со звёздочкой ловила и эти формы, то есть
требовала ошибки, — на теме `idor` это дало шесть ложных срабатываний подряд.
Запись разбита на формы, у которых второго чтения нет: `счет`, `счету`,
`счетом`, `счете` и отдельно `счетчик`. Форма «счета» из списка выпала намеренно
— она читается и как родительный единственного («счёта»), и как именительный
множественного («счета»), а различить их без морфологии нельзя. Остальные слова
списка проверены: у «объём», «учёт», «отчёт», «зачёт» ударение неподвижно, и
звёздочка в них законна.

### S-CODE-PUNCT { #S-CODE-PUNCT }

**Свод:** знак препинания ставится вне моноширинного фрагмента; падежные
окончания к коду не приклеиваются.

**Машина:** запятая, точка, точка с запятой или двоеточие непосредственно перед
закрывающей обратной кавычкой; русская буква сразу после закрывающей обратной
кавычки.

**Цена:** warning, потому что знак препинания внутри кода бывает частью кода —
`Cache-Control: no-store` цитируется вместе с двоеточием, `{"a": 1}` вместе с
запятыми. Правило смотрит только на позицию непосредственно перед закрывающей
кавычкой, что отбрасывает эти случаи, но не все. Отброшены отдельно ещё три
вида, где знак принадлежит записи, а не фразе вокруг неё: схема URI (`data:`),
ссылка на сущность XML или HTML (`&xxe;`, `&#38;` — без точки с запятой это не
сущность) и многоточие усечения (`%2553...`, `field[$ne]=...` — вынести его за
кавычки значит соврать про сам код).

### S-LIST-ORDER { #S-LIST-ORDER }

Заменяет `MD029`. Свод (7.1 п. 9) требует пояснять листинги
нумерованными выносками, а список, продолжающий выноски, законно начинается с
номера выноски: в `rest-and-graphql` внутри листинга стоят метки `(4)` и `(5)`,
и список под ним начинается с `4.`. `MD029` считает началом списка любой первый
пункт и такой замысел помечает. Своё правило проверяет то, что действительно
поломка: номера должны идти по возрастанию с шагом 1, начало — любое.

### S-LIST-MIX { #S-LIST-MIX }

Смешение пунктуации внутри одного списка. Свод различает три
вида списков: шаги (с прописной, точка в конце), продолжение фразы после
двоеточия (со строчной, `;`, последний `.`) и значения без пояснений (без
знаков). Машина проверяет только однородность: все пункты одного списка
заканчиваются одинаково. Какой из трёх видов уместен здесь — не проверяется,
поэтому warning.

### S-CODE-WIDTH { #S-CODE-WIDTH }

**Свод (7.1 п. 3):** длина строки в листинге ≤ 76 символов, проверяется
линтером.

**Машина:** строка внутри ограждённого блока длиннее 76 символов — ошибка.
Считаются символы, а не байты. Проверяется содержимое блока, не его ограждения.

**Цена:** порог применяется ко всем языкам одинаково, хотя 76 символов взяты из
ширины колонки вёрстки, а не из привычек языка. Это и есть смысл ограничения:
листинг, не влезающий в колонку, читатель читает с горизонтальной прокруткой,
и на телефоне не читает вовсе.

### S-CODE-LEN { #S-CODE-LEN }

**Свод (7.1 п. 4):** длина блока ≤ 25 строк для разбираемого примера, 40 —
абсолютный максимум.

**Машина:** два порога одного правила. Свыше 25 строк — предупреждение, свыше
40 — ошибка. Ровно так, как сформулировано в своде: 25 — норма разбираемого
примера, 40 — граница, за которую нельзя.

**Цена:** «разбираемый пример» от «фрагмента» машина не отличает, поэтому норма
25 применяется ко всем блокам. Отсюда и уровень: предупреждение, а не ошибка.

### Ссылки: S-EXT-IN-BODY и S-LINK-* { #links }

Шесть правил живут в `tools/linkcheck.py` и вместе отвечают на пункт DoD 17
«Битых ссылок нет». Правила из части 6 здесь только по соседству: границу
проводит `SCOPE.md` § 6, а блокирующий список — 9.4.

**S-EXT-IN-BODY** (error) { #S-EXT-IN-BODY } — внешний адрес законен только в
блоке «Источники». В остальных блоках он может стоять только носителем
содержания, а это ровно то, что запрещает граница самодостаточности. Адрес
внутри обратных кавычек правило не видит: `https://evil.com` в теме про `CORS` —
пример разбора, а не ссылка.

**S-LINK-BARE** (error) { #S-LINK-BARE } — адрес в прозе без угловых скобок.
python-markdown голые адреса не размечает, поэтому такой адрес доедет до
читателя текстом, который нельзя нажать: снаружи это выглядит как битая ссылка,
хотя сам адрес жив. Либо `<…>`, либо обратные кавычки, если это пример.

**S-LINK-TOPIC** (error) { #S-LINK-TOPIC } — ссылка на тему, которой нет.
Проверяются два места: пункт блока «Дальше», начинающийся с идентификатора, и оборот
«тема `id`» в прозе («Возврат к теме `cookies`», «см. тему `http-basics`» — так
написаны все тридцать девять перекрёстных ссылок корпуса). Ненаписанная тема
называется номером плана («Тема 1.6.04»), и это разница по существу: номер
читатель поймёт как обещание, идентификатор — как ссылку.

Два сужения, оба проверены фикстурой. Слово «тема» с указательным
(«в **этой** теме `Set-Cookie` разбирается ниже») говорит о самой странице, и
код после него называет не тему. Идентификатор темы — строчная латиница с
дефисами, поэтому `Set-Cookie`, `HttpOnly` и `SameSite` ссылкой на тему быть не
могут. Шапку темы правило не смотрит: `пререквизиты:` сверяют `C-HEAD-PREREQ` и
`C-REF-TOPIC`, и два сообщения об одном дефекте — это шум.

**S-LINK-MD** (error) { #S-LINK-MD } — markdown-ссылка, чья внутренняя цель не
разрешается: файла нет, анкоря на странице нет, цель пустая. В сегодняшнем
корпусе markdown-ссылок нет ни одной, и правило молчит; заведено оно потому, что
9.4 относит битую внутреннюю ссылку и битый анкорь к блокирующим, а молчащее
правило проверяется фикстурой, а не надеждой. Анкорь считается тем же способом,
что в сборке (`pymdownx.slugs.slugify`, `case="lower"`): умолчание
python-markdown выбрасывает всё вне ASCII, и от «## 3. Механика» остался бы
анкорь «3».

**S-LINK-SOURCE-URL** (warning) { #S-LINK-SOURCE-URL } — адрес в сноске блока «Источники»
не совпадает с `url` реестровой записи, названной в той же сноске: читатель и
реестр смотрят в разные места. Уровень предупреждения, а не ошибки, потому что
расхождение бывает законным — сноска ведёт на сам файл, реестр на страницу
документа. Так стоит одна из тридцати девяти ссылок корпуса.

**S-LINK-EXT** (warning) { #S-LINK-EXT } — внешний адрес не открылся. Уровень
задан сводом: 9.4 относит битую внешнюю ссылку к предупреждениям. Проверка ходит
в сеть и потому включается флагом: `tools/check.py --external`. Причина не в
скорости — красный вердикт `make check` должен означать «текст сломан», а не
«сети нет».

Запрос делается методом `GET` и читает первые байты ответа. `HEAD` был бы
дешевле, но врёт: `portswigger.net` отвечает на `HEAD` кодом 404 на страницы,
которые по `GET` отдаёт с кодом 200, — три живые ссылки в `tls-and-proxy` были
объявлены битыми на пустом месте. Хост, который отказывает автоматическому
клиенту по политике (`www.w3.org` за проверкой Cloudflare), снимается
исключением в `tools/exceptions.yaml`: правило «адрес отвечает» к такому хосту
неприменимо в принципе.

### S-PLACEHOLDER { #S-PLACEHOLDER }

Тема начинается не с пустого файла, а с копии `templates/L1.md`, `L2.md` или
`L3.md`: 11.1 ставит на стадии 3 автоматическую проверку «соответствие шаблону
уровня». Всё, что автор обязан заменить или удалить, размечено в шаблоне
угловыми скобками: `⟨механизм⟩` на месте значения, `⟨Автору⟩` в начале врезки с
нормой блока. Правило ловит любую такую скобку — и парную вставку, и одиночный
знак.

Разметка выбрана так, чтобы правило было безошибочным по построению: `⟨` и `⟩`
(U+27E8, U+27E9) не встречаются ни в одной теме, ни в файлах свода, ни в
инструментах. Кавычки-ёлочки «…» и ASCII-угол `<` — другие знаки: `<details>`
блока 12 и автоссылка `<https://…>` законны и правилу не видны.

Проверяется `raw`, а не `prose`: заполнитель во frontmatter (`⟨механизм⟩` в
`teaches`) и заполнитель внутри листинга — та же недоделка, что в абзаце, и
прячется он там лучше. Уровень — ошибка: тема с незаменённым заполнителем не
дописана, а публикация недописанной темы и есть то, что `make check` обязан
остановить.

Оставленную вводную врезку шаблона ловит вторым способом markdownlint: врезка
стоит перед `h1`, и MD041 требует, чтобы первым после frontmatter шёл заголовок.
Одна недоделка даёт два сообщения от разных инструментов — это дешевле, чем
надеяться на одно.

Сами шаблоны ни Vale, ни markdownlint, ни `lint_style.py` по умолчанию не
смотрят: их globs — `content/**/*.md`. Шаблоны проверяет `make lint-selftest`, и
двумя утверждениями сразу: скопированный в дерево тем шаблон проходит все
правила контентной модели (тема начинается зелёной), и в нём есть заполнители
(разметка на месте). Уровень, у которого шаблона нет, там же виден как
незакрытое утверждение.

## 7. Запрещённые конструкции — 6.5

Список 6.5 разложен на шесть правил не по темам, а по цене ошибки: конструкции,
у которых законного прочтения нет, отделены от тех, у которых оно бывает.

### L-BANNED { #L-BANNED }

«Просто», «легко», «очевидно», «всего лишь», «элементарно», «не составит
труда», «как известно», «всем понятно» — со словоформами.

Границы слова заданы вручную: `\b` в движке Vale работает по ASCII и на
кириллице не срабатывает, поэтому каждое выражение обрамлено классами
`(?:^|[^\p{L}\p{N}_-])` и `(?:[^\p{L}]|$)`. Без правой границы «скоро» ловилось
внутри «скорость» — десять ложных срабатываний в первом прогоне.

Термин спецификации, совпадающий с запрещённым словом, снимается исключением:
«простой запрос» в теме про `CORS` — это `simple request` из Fetch Standard.
Два таких срабатывания в корпусе, оба в `cors.md`, оба в `tools/exceptions.yaml`.

### L-CLERICAL { #L-CLERICAL }

Уровень error: «является», «представляет собой», «имеет место»,
«осуществляется», «производится настройка», «в целях», «в связи с тем, что», а
также местоимение «данный» в формах, где оно не совпадает с существительным
«данные»: `данный`, `данная`, `данное`, `данного`, `данному`, `данной`.

### L-CLERICAL2 { #L-CLERICAL2 }

Уровень warning: обороты, где местоимение «данный» стоит во множественном
числе, — «в данных условиях», «данные меры», «данным образом», «данными
методами». Правило ловит оборот, а не словоформу, и в этом вся его конструкция.

**Почему не словоформа.** Формы `данные`, `данных`, `данным`, `данными` у
местоимения и у существительного «данные» совпадают буквально, и различить их
по одному слову нельзя: у существительного нет единственного числа, а значит,
нет и признака, по которому его отличить. Различает контекст, а контекст
регулярному выражению не виден. Зато местоимение во множественном числе живёт в
закрытом наборе оборотов канцелярита, где существительное невозможно: данные не
бывают мерой, условием, образом действия. Список оборотов — в правиле.

**Чем это кончилось у прежней редакции.** Правило ловило форму и просило автора
посмотреть глазами. При 28 темах это давало 28 срабатываний и выглядело
списком для ревизии; при 39 темах — 311, и все 311 до одного были
существительным. Ни одного местоимения за всю историю проекта правило не нашло.
Список, который никто не дочитывает до конца, ревизией быть перестал, а
настоящие предупреждения в нём утонули: на 397 предупреждений корпуса 311
приходилось на это правило.

**Чем платим.** Полнота: оборот вне списка правило пропустит. Это осознанный
размен. Единственное число — то есть подавляющая часть этого канцелярита в
русском тексте — ловится `L-CLERICAL` на уровне error и не зависит от списка;
множественное же без единственного почти не встречается, поэтому пропущенный
оборот почти всегда стоит рядом с пойманной ошибкой. Правило, которое врёт в
ста процентах случаев, полезнее не тем, что ловит больше, а тем, что его
читают.

### L-EVAL { #L-EVAL }

«Мощный», «удобный», «эффективный», «гибкий» со словоформами.
Замена требуется фактом, а не другим прилагательным.

### L-FILLER { #L-FILLER }

«Мы в этой статье», «прежде чем перейти к», «стоит отметить, что»,
«не секрет, что», «рассмотрим подробнее».

### L-NAV { #L-NAV }

Навигация словом вместо якорной ссылки. Правило сужено до трёх
образцов: текст ссылки из запрещённого списка (`[здесь]`, `[по ссылке]`,
`[читать далее]`), «см. выше» / «смотрите ниже», «в таблице ниже» / «на схеме
выше» и подобные пары «объект + направление». Одиночные «слева», «справа», «по
ссылке» правило не трогает, и это не поблажка: в корпусе «крайний слева
элемент `X-Forwarded-For`» — описание структуры заголовка, «переходит по ссылке
из письма» — описание действия жертвы, «Описание схемы» — обязательный по 7.4
блок. Все три законны, и правило, помечающее их, помечает язык, а не навигацию.

Половина правила ищет текст ссылки в исходнике (`NavLink.yml`, `scope: raw`), а
не в прозе: Vale снимает разметку прежде, чем отдать текст правилам, и до
правила по прозе от `[здесь](#a)` доходит одно слово «здесь» — неотличимое от
законного «переходит по ссылке из письма». Идентификатор у обеих половин один.

### L-TIMELESS { #L-TIMELESS }

«Сейчас», «в настоящее время», «на сегодняшний день»,
«современный», «скоро», «недавно». Слово «новый» из списка 6.5 в правиле
отсутствует: в корпусе все тринадцать вхождений — значение «только что
созданный» («выдаётся новый токен», «каждый новый поддомен требует правки»), а
не «недавно появившийся». Ни одного запрещённого употребления правило бы не
поймало, зато дало бы тринадцать ложных. Значение «новый = современный» ушло в
§ 9. Уровень warning: «современный» в заголовке темы, взятом из плана автора,
— замечание к плану, а не к вёрстке.

### L-EMOJI { #L-EMOJI }

Эмодзи по диапазонам Unicode и восклицательный знак в прозе. Код
Vale не смотрит, поэтому `if (!stored)` и `!important` не срабатывают. Именно
на этом классе видна разница с `tools/stoplist.py`, который ищет по сырому
тексту: у него `!` в коде даёт ложное срабатывание, и это известная его
слабость, а не повод его выключить — он проверяет свой список и запускается
вместе с остальными.

Капслок отдельным правилом не проверяется: в этом гайде заглавными пишутся
`RFC`, `MUST`, `SHOULD`, `ASVS`, `WSTG`, `CWE`, имена полей заголовка и коды
ответов, и правило «три заглавные подряд» помечало бы почти каждую строку. § 9.

## 8. Как объяснять — 6.6

Из 6.6 машине сдаются два пункта. Первый уже описан: счётчик новых терминов
`G-NEW-PAGE`. Второй — наличие места «Откуда это взялось» (`C-BODY-ORIGIN`,
`SCHEMA.md` § 6): машина ищет подстроку и видит, что рассказ есть, а не что в
нём написано. Остальные шесть — «пример предшествует определению», «контраст на
минимально различающихся парах», «у аналогии есть граница», «история проблемы
не в тексте», «задача формулируется до решения», «каждое упрощение
маркировано» — требуют понимания смысла абзаца.

Три из них имеют слабый структурный признак, и он вынесен не сюда, а в
проверку композиции темы (`C-*`, `SCHEMA.md`): наличие блока, наличие врезки,
наличие раскрытия у аналогии проверяются как наличие блока в скелете части 4, а
не как свойство текста. Это честная граница: машина видит, что врезка есть, и
не видит, что в ней написано.

## 9. Что проверяется глазами

Список закрытый: он и есть ответ на вопрос «что означает зелёный `make check`».
Зелёный прогон означает, что не нарушено ничего из § 2, и не означает ничего о
пунктах ниже.

| Пункт свода | Почему не машине |
|---|---|
| 6.1 повелительное наклонение, «мы» и «я» по местам | нужен морфологический разбор |
| 6.1 настоящее время | то же |
| 6.1 активный залог, три разрешённых пассива | признака разрешённого пассива нет |
| 6.1 отглагольные существительные, цепочки родительных | частотные образцы уже в `L-CLERICAL`, остальное — разбор |
| 6.1 «Чтобы X, сделайте Y» — условие перед действием | порядок частей сложного предложения |
| 6.1 один шаг процедуры — одно действие, с глагола | нужен разбор шага |
| 6.1 раздел без подзаголовка ≤ 1,5 экрана | «экран» не определён в исходнике |
| 6.2 обязательное против необязательного по ГОСТ | машина не знает, что автор имел в виду |
| 6.3 sentence case в заголовках | `SPA`, `REST`, `GraphQL` в заголовке законны |
| 6.3 отсутствие кавычек вокруг латиницы | «ёлочки» цитаты и «ёлочки» вокруг латиницы неотличимы |
| 6.3 транслитерация прижившихся заимствований | требует списка всех неприжившихся |
| 6.4 вложенные „лапки“ | нужен разбор вложенности |
| 6.4 неразрывный пробел перед тире | сливается с `L-DASH` |
| 6.4 какой из трёх видов списка уместен | `S-LIST-MIX` проверяет только однородность |
| 6.5 «новый» в значении «современный» | 13 из 13 вхождений в корпусе — «только что созданный» |
| 6.5 капслок | `RFC`, `MUST`, `ASVS` пишутся заглавными законно |
| 6.5 тон: снисходительность, бравада, запугивание, юмор | смысл |
| 6.6 всё, кроме счётчика терминов | смысл |
| 6.7 понятность | пересказ на живых читателях, think-aloud, журнал вопросов |

## 10. Как запускать

```
make check          # все проверки, код возврата — вердикт
make check-lang     # только Vale, с исключениями
make check-md       # только markdownlint
make lint-selftest  # у каждого правила есть фикстура: ловит своё, молчит на законном
make links          # ссылки, включая внешние адреса: это единственная проверка с сетью
```

Отдельно инструменты вызываются так:

```
tools/bin/vale --config=tools/vale/.vale.ini content
tools/node/node_modules/.bin/markdownlint-cli2 --config tools/markdownlint.jsonc
```

Вызванные напрямую, они печатают все срабатывания, включая снятые
исключениями, — это способ увидеть, что именно снято.
