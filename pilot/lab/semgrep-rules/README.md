# Лаба semgrep-rules: напиши правило

Стенд на двух языках с подставленными дефектами и чистым кодом похожей формы.
Разметка ожиданий готова, файл правил — заготовка: на ней прогон разметки не
сходится. Задача — довести правила до схождения, не подгоняя разметку.

## Файлы

| файл | что это |
|---|---|
| `code/py/`, `code/go/` | стенд: по шесть файлов на язык |

Стенд `code/` намеренно общий с лабой `sast-principles` (там по нему
учатся читать отчёты): в обеих лабах лежат две одинаковые копии дерева,
синхронизируются вручную.
| `rules/sql-string-built.yaml` | заготовка правила для Python |
| `rules/sql-string-built.py` | разметка ожиданий для него |
| `rules/sql-built-go.yaml` | заготовка правила для Go |
| `rules/sql-built-go.go` | разметка ожиданий для него |
| `check.sh` | прогон разметки; код возврата 0 — сошлось |
| `hint.md` | одна подсказка |
| `solution/` | готовые правила и та же разметка; открывается после попытки |

## Как запускать

```text
cd pilot/lab/semgrep-rules
./check.sh
../../../.venv-tools/bin/semgrep --config=rules/ --metrics=off \
    --no-git-ignore --jobs 1 code/
```

Сети прогон не требует: правила локальные, реестр не запрашивается.

## С чего начинается прогон разметки

```text
0/2: 2 unit tests did not pass:
	x sql-built-go
	missed lines: [12], incorrect lines: []
	x sql-string-built
	missed lines: [], incorrect lines: [19]
```

`missed lines` — правило промолчало там, где размечено `ruleid:`: пропуск.
`incorrect lines` — сработало там, где размечено `ok:`: ложное срабатывание.
У правила для Go пропуск, у правила для Python — ложное срабатывание.

**Цель одной фразой:** довести файл правил до состояния, когда `check.sh`
печатает «All tests passed» на обоих языках, а прогон по стенду даёт оба
подставленных дефекта на каждом языке и не больше одного ложного
срабатывания.

Ложное срабатывание, которое останется, — одно, в стенде на Python: имя
таблицы, сверенное с замкнутым множеством. Снять его правилом нельзя, и
почему — сказано в теме `sast-false-positives`. На стенде Go то же место
правилом не ловится по другой причине: там `fmt.Sprintf` стоит прямо в доводе
вызова, а не в присваивании.

## Отдельная задача «почини»

Заготовка для Python срабатывает на запросе, где подставлять нечего вовсе.
Убрать это срабатывание, не потеряв ни одного из двух дефектов. Решение — в
`solution/`, открывается после своей попытки.

## Сброс

Чтобы вернуть заготовки правил из `rules/` в исходное состояние,
восстановите их из репозитория гайдбука.

## Удаление

```bash
rm -rf pilot/lab/semgrep-rules
```

Ничего вне этого каталога лаба не создаёт и не меняет.
