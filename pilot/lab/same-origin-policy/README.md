# Лаба: политика одного источника и `postMessage`

Формат Secure Code Game: чините `code.js`, пока `hack.mjs` и `tests.mjs`
не станут зелёными одновременно.

**Цель одной фразой:** добиться, чтобы `hack.mjs` вышел с кодом 0, а
`tests.mjs` продолжил выходить с кодом 0.

Три статических сервера на `127.0.0.1` играют три источника: приложение
(8081), чужая площадка (8082) и доверенный виджет (8083). Чужая площадка
проводит пять опытов над приложением, и четыре из них политика одного
источника останавливает сама. Пятый — `postMessage` — она не
останавливает: сообщение доходит до обработчика в `code.js`, и проверять
отправителя должен обработчик.

Шестой опыт идёт с другой стороны: доверенный виджет взломан и посылает
настройку не той формы. Origin у сообщения при этом настоящий, так что
проверки одного origin для него мало — HTML Living Standard требует в
разделе 9.3.2.1 проверять и форму данных.

Всё исполняется локально: сеть браузеру перекрыта флагом
`--host-resolver-rules=MAP * ~NOTFOUND, EXCLUDE 127.0.0.1`, так что
никакое обращение наружу из лабы не разрешится.

## Запуск

Нужен Node.js 20 или новее (проверено на v26.7.0) и headless-браузер из
кеша puppeteer, который уже стоит в `tools/node`. Обвязка находит и то и
другое сама; переопределяется переменной `CHROME_PATH`.

```bash
cd pilot/lab/same-origin-policy
node tests.mjs   # ожидается: Упало проверок: 0, код возврата 0
node hack.mjs    # ожидается: ЭКСПЛОЙТ СРАБОТАЛ, код возврата 1
```

Прогнать то же против образцового решения:

```bash
LAB_TARGET=solution.js node hack.mjs   # ЭКСПЛОЙТ НЕ СРАБОТАЛ, код 0
LAB_TARGET=solution.js node tests.mjs  # Упало проверок: 0, код 0
```

Посмотреть глазами в своём браузере:

```bash
node serve.mjs   # печатает три адреса и не завершается; Ctrl+C — стоп
```

## Файлы

| Файл | Что это |
|---|---|
| `code.js` | То, что чините; отдаётся приложению как `/code.js` |
| `hack.mjs` | Шесть опытов; зелёный, когда пятый и шестой перестали работать |
| `tests.mjs` | Функциональность; должна остаться зелёной |
| `hint.md` | Одна подсказка |
| `solution.js` | Образцовое решение |
| `serve.mjs` | Три источника на `127.0.0.1`: 8081, 8082, 8083 |
| `labtarget.mjs` | Запуск браузера без сети |
| `app/`, `evil/`, `widget/` | Страницы трёх источников |

## Отдельная задача «почини»

Проверка «настройка из своего документа применяется» проходит до вашей
правки и обязана проходить после. Приложение посылает настройку само
себе, и обработчик слушает эти сообщения наравне с сообщениями виджета:
список доверенных адресов из одного виджета ломает её.

Наблюдаемый критерий: `node tests.mjs` печатает `Упало проверок: 0` и
выходит с кодом 0 после того, как `node hack.mjs` вышел с кодом 0.

Замер на этой лабе — четыре варианта `code.js`:

| Что в обработчике | `hack.mjs` | `tests.mjs` |
|---|---|---|
| ничего не проверяется (исходный `code.js`) | 1 | 0 |
| сверяется один адрес — виджет | 1 | 1 |
| список верный, форма данных не проверяется | 1 | 0 |
| список и форма данных (`solution.js`) | 0 | 0 |

## Сброс

Состояние держится в памяти процессов, между запусками ничего не
остаётся: серверы поднимаются на время прогона и гасятся после.
Чтобы вернуть исходный `code.js`, восстановите его из репозитория
гайдбука.

## Удаление

```bash
rm -rf pilot/lab/same-origin-policy
```

Ничего вне этого каталога лаба не создаёт и не меняет. Кеш
headless-браузера в `~/.cache/puppeteer` лаба не ставила и не трогает.
