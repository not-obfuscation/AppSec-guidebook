# Лаба jwt-attacks: алгоритм, выбранный токеном

Кабинет отдаёт роль по JWT, подписанному сервером на RS256. Проверяющий читает
поле `alg` из заголовка токена и по нему решает, чем сверять подпись. Заголовок
приходит от предъявителя, поэтому предъявитель управляет проверкой: `alg=none`
снимает подпись, `alg=HS256` на открытом ключе сервера даёт путаницу ключей.
Оба обхода выдают роль `admin` без закрытого ключа.

## Файлы

| файл | что это |
|---|---|
| `code.py` | уязвимый модуль: алгоритм проверки берётся из токена |
| `solution.py` | образец починки: список алгоритмов закрыт (`["RS256"]`) |
| `hack.py` | эксплойт: alg=none и HS/RS confusion; 0 — почат, 1 — уязвимо |
| `tests.py` | функциональность кабинета: должна остаться зелёной |
| `labtarget.py` | загрузка проверяемого модуля (`LAB_TARGET=solution.py`) |
| `hint.md` | одна подсказка |

## Как запускать

```text
cd pilot/lab/jwt-attacks
../../../.venv-tools/bin/python hack.py       # против code.py: 2 из 2 опытов
../../../.venv-tools/bin/python tests.py      # функциональность: 0 упало
LAB_TARGET=solution.py ../../../.venv-tools/bin/python hack.py    # 0 опытов
LAB_TARGET=solution.py ../../../.venv-tools/bin/python tests.py   # 0 упало
```

## Цель одной фразой

Добиться, чтобы `hack.py` вышел с кодом 0 (ни `none`, ни `HS256` не приняты), а
`tests.py` продолжил выходить с кодом 0 (честные RS256 проходят).

## Задача «почини»

Закройте список принимаемых алгоритмов литералом `["RS256"]` и проверяйте
подпись строго открытым ключом сервера. Не читайте `alg` из токена.

## Правило SAST

`pilot/semgrep/jwt-alg-from-token.yaml` ловит алгоритм, взятый из заголовка,
`verify_signature=False` и `none` в списке: на `code.py` одна находка, на
`solution.py` — ноль. Сверка: `.venv-tools/bin/python pilot/semgrep/check.py jwt-alg`.

Всё локально, к сети не обращается, применимо только к этой лабе.
