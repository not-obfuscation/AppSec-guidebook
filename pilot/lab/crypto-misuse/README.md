# Лаба crypto-misuse: годный шифр, применённый негодным способом

Приложение хранит состояние сессии на клиенте под AES и само же его читает.
Профиль зашифрован режимом ECB, сеанс — режимом счётчика с одним постоянным
одноразовым значением. Метки целостности нет ни у того, ни у другого, а
расшифровке присланного ничего не предшествует. Ключ приложения атакующему
неизвестен и не нужен: ломается не шифр, а способ его применения.

## Файлы

| файл | что это |
|---|---|
| `code.py` | уязвимое приложение: ECB для профиля, CTR с постоянным nonce для сеанса |
| `solution.py` | образец починки: один AES-GCM и проверка метки до разбора |
| `hack.py` | эксплойт: три опыта и контрольный; возврат 0 — почин, 1 — уязвимо |
| `tests.py` | функциональность профиля и сеанса: должна остаться зелёной |
| `sandbox.py` | ключ приложения и разбор состояния сессии, всё в памяти |
| `labtarget.py` | загрузка проверяемого модуля (`LAB_TARGET=solution.py`) |
| `hint.md` | одна подсказка |

## Как запускать

```text
cd pilot/lab/crypto-misuse
../../../.venv-tools/bin/python hack.py      # против code.py: 3 обхода открыты
../../../.venv-tools/bin/python tests.py     # функциональность: 0 упало
LAB_TARGET=solution.py ../../../.venv-tools/bin/python hack.py    # 0 обходов
LAB_TARGET=solution.py ../../../.venv-tools/bin/python tests.py   # 0 упало
```

Числа детерминированы: перебора нет, все три опыта воспроизводимы.

## Три опыта эксплойта

1. **ECB.** Длинное однобайтовое поле профиля даёт два выровненных одинаковых
   блока открытого текста; в шифротексте им достаются два одинаковых блока —
   структура видна без ключа (пять блоков, четыре различных).
2. **Повтор nonce.** Два сеанса под одним значением счётчика складываются в
   сумму открытых текстов. Зная свой сеанс, атакующий вычитает поток ключа и
   читает чужой: `user=victim01;role=admin;credit=9…`.
3. **Податливость.** Зная своё поле `role=user0`, атакующий правит те же байты
   шифротекста и получает `role=admin` — расшифровка проходит без ошибки,
   потому что целостность не проверяется.

## Цель одной фразой

Добиться, чтобы `hack.py` вышел с кодом 0 (все три обхода закрыты, контрольный
опыт цел), а `tests.py` продолжил выходить с кодом 0.

## Задача «почини»

Замените обе схемы одним аутентифицированным режимом и проверяйте метку до
разбора присланного. Шесть проверок функциональности должны остаться зелёными:
выданные профиль и сеанс читаются обратно со всеми тремя полями.

## Правило SAST

`pilot/semgrep/aes-mode-ecb-or-static-iv.yaml` ловит режим ECB и постоянное
одноразовое значение в вызове шифрования: на `code.py` находки есть, на
`solution.py` — ноль.
Сверка: `.venv-tools/bin/python pilot/semgrep/check.py aes-mode`.

Всё исполняется локально, к сети не обращается и применимо только к этой лабе.

## Сброс

Состояние держится в памяти процесса, между запусками ничего не
остаётся. Чтобы вернуть исходный `code.py`, восстановите его из
репозитория гайдбука.

## Удаление

```bash
rm -rf pilot/lab/crypto-misuse
```

Ничего вне этого каталога лаба не создаёт и не меняет.
