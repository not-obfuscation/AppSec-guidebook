# Лаба: подделка межсайтового запроса

Формат Secure Code Game: чините `code.mjs`, пока `hack.mjs` и `tests.mjs`
не станут зелёными одновременно.

**Цель одной фразой:** добиться, чтобы `hack.mjs` вышел с кодом 0, а
`tests.mjs` продолжил выходить с кодом 0.

Кабинет подписки на `bank.example:8125` умеет менять адрес почты. Кто
прислал запрос, кабинет решает по одной сессионной cookie: другого
признака у него нет. На `evil.test:8126` лежит страница-приманка, которая
отправляет в кабинет запрос сама. Три опыта показывают, что кабинет не
отличает свой запрос от чужого, два проверяют, что после починки кабинет
живой.

Два имени для браузера — два разных сайта, для сети — один и тот же
127.0.0.1. Всё исполняется локально: браузеру разрешены только эти два
имени, остальные не резолвятся флагом
`--host-resolver-rules=MAP bank.example 127.0.0.1, MAP evil.test 127.0.0.1, MAP * ~NOTFOUND`.

## Запуск

Нужен Node.js 20 или новее (проверено на v26.7.0) и headless-браузер из
кеша puppeteer, который уже стоит в `tools/node`. Обвязка находит и то и
другое сама; переопределяется переменной `CHROME_PATH`.

```bash
cd pilot/lab/csrf-mechanics
node tests.mjs   # ожидается: ТЕСТЫ ПРОЙДЕНЫ 7 из 7, код возврата 0
node hack.mjs    # ожидается: ЭКСПЛОЙТ СРАБОТАЛ, код возврата 1
```

Прогнать то же против образцового решения:

```bash
LAB_TARGET=solution.mjs node hack.mjs    # ЭКСПЛОЙТ НЕ СРАБОТАЛ, код 0
LAB_TARGET=solution.mjs node tests.mjs   # ТЕСТЫ ПРОЙДЕНЫ, код 0
```

Посмотреть глазами в своём браузере: адреса `bank.example` и
`evil.test` в обычном браузере не разрешатся, потому что резолвер
подменяет их только внутри лабы. Пропишите их в `/etc/hosts` на
127.0.0.1 либо смотрите прогон.

```bash
node serve.mjs   # печатает адреса и не завершается; Ctrl+C — стоп
```

| `tests.mjs` | Функциональность кабинета; должна остаться зелёной |
| `hint.md` | Одна подсказка |
| `solution.mjs` | Образцовое решение |
| `serve.mjs` | Кабинет и страница-приманка на петле |
| `labtarget.mjs` | Запуск браузера без сети |

## Почему вход выполняется заново перед каждым опытом

Cookie без явного атрибута `SameSite` браузер отправляет с кросс-сайтовым
POST только первые две минуты после того, как её выставили; дальше она
ведёт себя как `SameSite=Lax`. Проверено прогоном на
`HeadlessChrome/152.0.7977.42`: тот же POST через 135 секунд после входа
приходит без cookie. Если бы `hack.mjs` не входил заново, опыт 1
зависел бы от того, сколько времени прошло, а не от того, есть в кабинете
защита или нет.

## Отдельная задача «почини»

Опытов, которые надо погасить, два, и правка одного оставляет второй.
Опыт 1 отправляет POST-форму с чужого сайта. Опыт 2 делает то же
действие одним переходом методом GET — а обработчик читает параметры и
из строки запроса тоже. Починка, поставившая проверку только на POST,
оставит опыт 2 зелёным у атакующего.

Наблюдаемый критерий: `node hack.mjs` печатает `ЭКСПЛОЙТ НЕ СРАБОТАЛ` и
выходит с кодом 0, а `node tests.mjs` после этого по-прежнему печатает
`ТЕСТЫ ПРОЙДЕНЫ: 7 из 7`.

Замер на этой лабе — четыре варианта `code.mjs`:

| Что делает `code.mjs` | провалено в `hack.mjs` | в `tests.mjs` |
|---|---|---|
| решает по одной cookie, действие и на GET (исходный) | 2 | 0 |
| принимает только POST, токена нет | 1 | 0 |
| токен привязан к сессии, но проверяется только у POST | 1 | 0 |
| токен, только POST и явный `SameSite` (`solution.mjs`) | 0 | 0 |

Вторая строка стоит внимания. Запрет метода GET сам по себе не чинит
ничего: кросс-сайтовый POST формой уходит с сессионной cookie и
выполняется. Третья строка — зеркальная ошибка: токен настоящий и
привязан к сессии, но путь мимо проверки остался открытым.

## Сброс

Состояние держится в памяти процесса, между запусками ничего не
остаётся: серверы поднимаются на время прогона и гаснут после. Чтобы
вернуть исходный `code.mjs`, восстановите его из репозитория гайдбука.

## Удаление

```bash
rm -rf pilot/lab/csrf-mechanics
```

Ничего вне этого каталога лаба не создаёт и не меняет. Кеш
headless-браузера в `~/.cache/puppeteer` лаба не ставила и не трогает.
