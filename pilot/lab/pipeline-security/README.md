# Лаба pipeline-security: пять дефектов в описании конвейера

Одно и то же приветствие запроса на слияние, описанное двумя системами, и шесть
замечаний на двоих. Ни сети, ни форжа, ни контейнеров: подстановка значения в
команду шага воспроизводится локально, правила линтера лежат рядом.

## Файлы

| файл | что это |
|---|---|
| `.github/workflows/pr-greeter.yml` | описание для GitHub Actions, уязвимое |
| `.gitlab-ci.yml` | то же для GitLab CI, уязвимое |
| `*.example` | эталоны решения |
| `ci/build.sh` | сборка, которую конвейер запускает |
| `expand.py` | подстановка значения в команду шага: что уезжает в оболочку |
| `lint.py` | шесть правил по описаниям конвейера |
| `check.py` | проверялка: линтер, прогон подстановки, сохранность конвейера |
| `hint.md` | одна подсказка |
| `solution.md` | разбор решения |

## Как запускать

```text
cd pilot/lab/pipeline-security
python3 lint.py
python3 expand.py .github/workflows/pr-greeter.yml 'Опечатка"; id; echo "'
python3 expand.py .gitlab-ci.yml 'Опечатка$(id)'
python3 check.py
```

Прогон подстановки на заголовке атакующего печатает вывод команды `id` — это и
есть выполнение чужого кода на сборочной машине.

## Задача

Починить оба описания конвейера так, чтобы линтер молчал, подстановка ни на
одном из трёх заголовков команду не выполняла, а конвейер продолжал делать свою
работу: печатать приветствие, запускать сборку и выкладывать результат.

Критерий наблюдаемый: `check.py` печатает «зачтено». Третья его проверка стоит
там намеренно — задача решается не удалением шагов.

## Сброс

Чтобы вернуть исходные `.github/workflows/pr-greeter.yml` и
`.gitlab-ci.yml`, восстановите их из репозитория гайдбука.

## Удаление

```bash
rm -rf pilot/lab/pipeline-security
```

Ничего вне этого каталога лаба не создаёт и не меняет.
