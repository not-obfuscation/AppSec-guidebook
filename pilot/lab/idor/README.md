# Лаба: горизонтальная эскалация и IDOR

Формат Secure Code Game: чините `code.py`, пока `hack.py` и `tests.py`
не станут зелёными одновременно.

**Цель одной фразой:** добиться, чтобы `hack.py` вышел с кодом 0, а
`tests.py` продолжил выходить с кодом 0.

Всё исполняется локально, только стандартной библиотекой Python, без
сети и без Docker. HTTP не поднимается: функции кабинета вызываются
напрямую. Приёмы из `hack.py` привязаны к этой лабе и применимы только
к ней.

## Запуск

Нужен Python 3.9 или новее. Проверено на 3.14.7.

```bash
cd pilot/lab/idor
python3 tests.py   # ожидается: упало 0, код возврата 0
python3 hack.py    # ожидается: ЭКСПЛОЙТ СРАБОТАЛ, код возврата 1
```

Прогнать те же проверки против образцового решения:

```bash
LAB_TARGET=solution.py python3 hack.py
LAB_TARGET=solution.py python3 tests.py
```

## Что проверяет эксплойт

| Опыт | Приём | Что получает атакующий |
|---|---|---|
| 1 | соседний номер счёта | чужой счёт целиком |
| 2 | тот же номер в изменяющей операции | подмена адреса доставки чужого счёта |
| 3 | UUID из ленты компании | счёт, номер которого не угадать |
| 4 | контроль: свой счёт | доступ должен остаться |

Опыт 3 — про то, что непредсказуемый идентификатор не защита: он
приезжает атакующему из соседней функции, а не подбирается.

## Файлы

| Файл | Что это |
|---|---|
| `code.py` | То, что чините |
| `hack.py` | Эксплойт; зелёный, когда атака перестала работать |
| `tests.py` | Функциональность; должна остаться зелёной |
| `hint.md` | Одна подсказка |
| `solution.py` | Образцовое решение |
| `labtarget.py` | Загрузчик проверяемого модуля |

## Сброс

Состояние держится в памяти процесса, между запусками ничего не
остаётся. Чтобы вернуть исходный `code.py`, восстановите его из
репозитория гайдбука.

## Удаление

```bash
rm -rf pilot/lab/idor
```

Ничего вне этого каталога лаба не создаёт и не меняет.
