# Лаба: отражённый XSS

Формат Secure Code Game: чините `code.mjs`, пока `hack.mjs` и `tests.mjs`
не станут зелёными одновременно.

**Цель одной фразой:** добиться, чтобы `hack.mjs` вышел с кодом 0, а
`tests.mjs` продолжил выходить с кодом 0.

Витрина поиска по базе знаний на `127.0.0.1:8121`. Присланная строка
возвращается в том же ответе дважды: в тексте сообщения и в значении
атрибута `value` поля ввода. Перед этим она «чистится» — из неё вырезают
слово `<script>`. Три опыта показывают, что этой чистки не хватает ни в
одном из двух мест, два опыта проверяют, что поиск после починки живой.

Всё исполняется локально: сеть браузеру перекрыта флагом
`--host-resolver-rules=MAP * ~NOTFOUND, EXCLUDE 127.0.0.1`, так что
никакое обращение наружу из лабы не разрешится.

## Запуск

Нужен Node.js 20 или новее (проверено на v26.7.0) и headless-браузер из
кеша puppeteer, который уже стоит в `tools/node`. Обвязка находит и то и
другое сама; переопределяется переменной `CHROME_PATH`.

```bash
cd pilot/lab/xss-reflected
node tests.mjs   # ожидается: Упало проверок: 0, код возврата 0
node hack.mjs    # ожидается: ЭКСПЛОЙТ СРАБОТАЛ, код возврата 1
```

Прогнать то же против образцового решения:

```bash
LAB_TARGET=solution.mjs node hack.mjs    # ЭКСПЛОЙТ НЕ СРАБОТАЛ, код 0
LAB_TARGET=solution.mjs node tests.mjs   # Упало проверок: 0, код 0
```

Посмотреть глазами в своём браузере:

```bash
node serve.mjs   # печатает адрес и не завершается; Ctrl+C — стоп
```

## Отдельная задача «почини»

Мест вставки два, и правка одного оставляет второе. Опыт 1 бьёт в текст
сообщения, опыт 2 — в значение атрибута `value`, и нагрузка у них
разная: во втором случае разметки нет вовсе, есть кавычка, закрывающая
атрибут раньше времени. Починка, закрывшая только первое место, оставит
опыт 2 зелёным у атакующего.

Наблюдаемый критерий: `node tests.mjs` печатает `Упало проверок: 0` и
выходит с кодом 0 после того, как `node hack.mjs` вышел с кодом 0.

Замер на этой лабе — четыре варианта `code.mjs`:

| Что делает `code.mjs` | провалено в `hack.mjs` | в `tests.mjs` |
|---|---|---|
| вырезает `<script>` на входе (исходный) | 3 | 0 |
| вырезает на входе `<` и `>` | 2 | 0 |
| экранирует сущностями только текст сообщения | 1 | 0 |
| экранирует оба места (`solution.mjs`) | 0 | 0 |

Вторая строка стоит внимания: из двух её провалов один — эксплойт в
значении атрибута, где разметки нет вовсе, а второй — опыт 5, контроль.
Запрос `счёт & <тариф>` после такой чистки показывается не так, как его
набрали. Чистка на входе ломает отображение и всё равно не закрывает
атрибут.

## Правило SAST

`pilot/semgrep/html-response-string-built.yaml` даёт находку на
`code.mjs` и молчит на `solution.mjs`:

```bash
.venv-tools/bin/python pilot/semgrep/check.py html-response
```

## Сброс

Состояние держится в памяти процесса, между запусками ничего не
остаётся: сервер поднимается на время прогона и гаснет после. Чтобы
вернуть исходный `code.mjs`, восстановите его из репозитория гайдбука.

## Удаление

```bash
rm -rf pilot/lab/xss-reflected
```

Ничего вне этого каталога лаба не создаёт и не меняет. Кеш
headless-браузера в `~/.cache/puppeteer` лаба не ставила и не трогает.
