# Решение

Подмена держится на двух свойствах установки: `pip` сливает кандидатов из всех
индексов и выбирает наибольшую версию. Значит, и закрывается она двумя
движениями, а не одним:

1. **Один источник истины.** `--index-url` на внутренний индекс, без
   `--extra-index-url` на публичный. Пакет с внутренним именем ищется только
   там, где ему положено быть.
2. **Пиннинг версии.** `shop-telemetry==1.0.0`: даже если публичный индекс
   как-то попадёт в конфигурацию, версия `9.9.9` не подойдёт под требование.

Эталон — `fix.sh.example`:

```bash
pip install --index-url "$PRIV" "shop-telemetry==1.0.0"
```

Чего решение не делает и почему это честно: оно не «запрещает публичный индекс
вообще» — публичные пакеты проекту нужны. Промышленный ответ — не один флаг, а
резервирование внутренних имён в публичном реестре (namespace/scope), чтобы
атакующий не мог зарегистрировать пакет с внутренним именем. На стенде это
показать нельзя, не выходя наружу, и потому оставлено ссылкой в теме.
