# Лаба supply-chain-threats: воспроизведи атаку и закрой источник

Два локальных индекса пакетов формата PEP 503 (каталоги `file://`). В обоих —
пакет `shop-telemetry`: во внутреннем версия `1.0.0` (`ORIGIN='internal'`), в
публичном — `9.9.9` (`ORIGIN='attacker'`). В публичном индексе лежит ещё и
`shop-telementry` — опечатка в одну букву.

Наружу не ходит ничего: оба индекса локальные, установка идёт из файлов.

## Файлы

| файл | что это |
|---|---|
| `registry/private-simple/` | внутренний индекс: `shop-telemetry 1.0.0` |
| `registry/public-simple/` | публичный индекс: `shop-telemetry 9.9.9` и опечатка |
| `demo.sh` | воспроизводит обе атаки и печатает, что установилось |
| `fix.sh.example` | эталон фикса задачи «почини» |
| `fix.sh` | заготовка в уязвимом состоянии — её и надо починить |
| `check.py` | запускает `fix.sh` и проверяет, что подмена закрыта |
| `hint.md` | одна подсказка |
| `solution.md` | разбор решения |

## Как запускать

```text
cd pilot/lab/supply-chain-threats
bash demo.sh          # увидеть обе атаки
python3 check.py      # проверить свой fix.sh
```

## Задача

`demo.sh` показывает: стоит добавить публичный индекс через `--extra-index-url`,
и `pip` берёт `9.9.9` вместо внутренней `1.0.0` — потому что из всех индексов он
выбирает наибольшую версию, не глядя, откуда она. Почини `fix.sh` так, чтобы
`shop-telemetry` снова ставился из внутреннего индекса. Критерий наблюдаемый:
`check.py` печатает «зачтено» и `ORIGIN` установленного пакета равен `internal`.

## Сброс

Чтобы вернуть заготовку `fix.sh` в исходное (уязвимое) состояние,
восстановите её из репозитория гайдбука. Временные окружения
пересоздаются при каждом запуске `demo.sh` и `fix.sh`.

## Удаление

```bash
rm -rf pilot/lab/supply-chain-threats /tmp/sc-lab-venv /tmp/sc-lab-fix-venv
```

Вне каталога лабы создаются только эти два временных окружения в `/tmp`;
кеш pip установка не трогает (`--no-cache-dir`).
