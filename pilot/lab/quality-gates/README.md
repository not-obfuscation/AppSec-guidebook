# Лаба quality-gates: договор о коде возврата

Четыре сохранённых отчёта настоящего сканера и заготовка гейта, который пока
отдаёт ноль всегда. Ни сети, ни сканера, ни контейнеров: отчёты сняты заранее
прогоном Semgrep 1.174.0 по подставленному дефекту и лежат рядом.

## Файлы

| файл | что это |
|---|---|
| `reports/clean.json` | находок нет |
| `reports/base.json` | один ERROR и один WARNING — состояние «до» |
| `reports/head.json` | тот же код плюс новый ERROR — состояние «после» |
| `reports/failed.json` | сканер упал: `results` пуст, `errors` — нет |
| `gate.py` | заготовка гейта в сломанном состоянии |
| `gate.py.example` | эталон решения |
| `check.py` | восемь прогонов: договор о коде возврата |
| `hint.md` | одна подсказка |
| `solution.md` | разбор решения |

## Как запускать

```text
cd pilot/lab/quality-gates
python3 gate.py reports/head.json
python3 gate.py reports/head.json --baseline reports/base.json
python3 check.py
```

## Задача

Написать гейт, выполняющий договор:

```text
0  порог не превышен
1  порог превышен — сборка останавливается
2  проверка не отработала — вердикта нет
```

Гейт настраивается тремя переменными среды: `SEVERITY` (с какого уровня
находка считается), `THRESHOLD` (сколько пропускается), `MODE` (`block` или
`warn`). При аргументе `--baseline` считаются только находки, которых не было
в базовом отчёте.

Критерий наблюдаемый: `check.py` печатает «зачтено» — все восемь прогонов
вернули ожидаемый код.

## Сброс

Чтобы вернуть заготовку `gate.py` в исходное состояние, восстановите
её из репозитория гайдбука.

## Удаление

```bash
rm -rf pilot/lab/quality-gates
```

Ничего вне этого каталога лаба не создаёт и не меняет.
