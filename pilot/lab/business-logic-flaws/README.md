# Лаба business-logic-flaws: правило предметной области без носителя

Магазин проводит заказ через четыре обработчика: корзина, скидка, оплата,
подтверждение. Механизмы исправны — артикул сверяется с каталогом, количество
приводится к целому, суммы складываются точно. Нарушены правила: отгрузка
после оплаты, цена из прайс-листа, скидка при выполненном условии. Носителем
этих правил был порядок вызовов, а порядок выбирает клиент.

## Файлы

| файл | что это |
|---|---|
| `code.py` | уязвимый магазин: состояния нет, цена из запроса |
| `solution.py` | образец починки: переходы состояний, каталог, пересчёт |
| `hack.py` | эксплойт: три нарушенных правила; возврат 0 — почин, 1 — уязвимо |
| `tests.py` | функциональность магазина: должна остаться зелёной |
| `labtarget.py` | загрузка проверяемого модуля (`LAB_TARGET=solution.py`) |
| `hint.md` | одна подсказка |

## Как запускать

```text
cd pilot/lab/business-logic-flaws
../../../.venv-tools/bin/python hack.py      # против code.py: 3 из 3 опытов
../../../.venv-tools/bin/python tests.py     # функциональность: 0 упало
LAB_TARGET=solution.py ../../../.venv-tools/bin/python hack.py    # 0 опытов
LAB_TARGET=solution.py ../../../.venv-tools/bin/python tests.py   # 0 упало
```

## Цель одной фразой

Добиться, чтобы `hack.py` вышел с кодом 0 (три правила удержаны), а `tests.py`
продолжил выходить с кодом 0 (магазин работает).

## Задача «почини»

Закройте три обхода в `code.py`. Подтверждение без оплаты, цена `0.01` вместо
`450.00` и скидка, пережившая уменьшение корзины, должны получить отказ. Шесть
проверок функциональности должны остаться зелёными: законный заказ на 450.00
проходит, скидка на пороге начисляется, неизвестный артикул отвергается.

## Правило SAST

`pilot/semgrep/money-value-from-request.yaml` ловит денежную величину, взятую
из тела запроса: на `code.py` одна находка, на `solution.py` — ноль.
Сверка: `.venv-tools/bin/python pilot/semgrep/check.py money-value`.

Всё исполняется локально, к сети не обращается и применимо только к этой лабе.
