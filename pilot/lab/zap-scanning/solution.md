# Решение

Открывается после своей попытки.

## Что подставлено в стенд

Тринадцать дефектов. Сканер нашёл не все, и это часть задачи.

| код | класс | где | вход нужен | ZAP нашёл |
|---|---|---|:-:|:-:|
| D-01 | отражённая XSS | `GET /search?q=` | нет | да |
| D-02 | SQL-инъекция | `GET /catalog?cat=` | нет | да |
| D-03 | обход каталога | `GET /files?name=` | нет | да |
| D-04 | нет CSP, X-Content-Type-Options, X-Frame-Options | все ответы | нет | да |
| D-05 | cookie сессии без HttpOnly, Secure, SameSite | `POST /login` | нет | да, только с входом |
| D-06 | хранимая XSS | `POST /profile` → `GET /profile` | да | да, только с входом |
| D-07 | SQL-инъекция в API | `GET /api/v1/products?filter=` | нет | только по спецификации |
| D-08 | доступ к чужому заказу | `GET /order?id=` | да | **нет** |
| D-09 | вертикальный контроль доступа | `GET /admin/users` | да | **нет** |
| D-10 | отрицательное количество даёт отрицательный итог | `POST /cart/checkout` | да | **нет** |
| D-11 | нет токена на изменяющих формах | `POST /profile`, `/cart/checkout` | да | да |
| D-12 | версия сервера в заголовке, текст исключения на странице ошибки | все ответы | нет | да |
| D-13 | обход каталога в API, ручка не связана со страницами | `GET /api/v1/reports?path=` | нет | только по спецификации |

Сверх подставленного сканер нашёл отражение полезной нагрузки на **странице
ошибки**: обработчик исключений печатает текст исключения без экранирования, а
в текст исключения попадает значение параметра. Это не планировалось: дефект
появился сам из «удобной» страницы ошибки. Он же печатает абсолютный путь к
каталогу стенда.

## Разбор семнадцати строк

Полная разметка — `key.yaml`, там у каждой строки записано «почему». Здесь —
три места, где ошибаются чаще всего.

**Строки 3 и 4 — дубли по неверному адресу.** В обеих полезная нагрузка стоит
**после решётки**. Фрагмент адреса на сервер не отправляется вовсе: правило
40026 работает настоящим браузером, дефект нашло верно, а адрес записало тот,
по которому вело браузер, а не тот, куда ушёл запрос. Настоящие места — строка
5 (заметка) и строка 6 (параметр `q`).

**Строки 14 и 15 — ложные срабатывания.** Правило 10096 ищет десятизначные
числа, похожие на время эпохи Unix, и находит номер заказа. Правило 10027 ищет
слова-приметы в комментариях разметки и находит `FIXME` про фотографии
самоваров. Оба правила сделали ровно то, что умеют; ни одно ничего не раскрыло.

**Строки 16 и 17 — не дефекты.** «User Agent Fuzzer» сообщает, что ответы на
разные значения `User-Agent` различаются. «Authentication Request Identified»
сообщает, что найдена форма входа, — это подсказка для настройки
аутентифицированного прогона, а не находка.

Итог: из семнадцати строк отчёта **одиннадцать** — работа для разработчика,
две ложные, две дубли, две информационные. На полном отчёте `auth-good.txt` то
же соотношение держится: 40 инстансов, из них 10 отдавать нельзя.

## Задача «почини»

Эталон — `solution/app.py`. Шесть проб `hack.py` закрыты, семь проверок
`tests.py` зелёные. Пять правок:

1. **Отражённая XSS.** `html.escape(q)` при выводе значения поиска.
2. **Страница ошибки.** Наружу уходит общая фраза, подробности — в журнал
   сервера. Экранировать текст исключения тоже можно, но тогда наружу
   по-прежнему уезжает абсолютный путь: правильнее не печатать его вовсе.
3. **SQL-инъекция.** Параметризованный запрос вместо склейки — в обеих ручках,
   и в HTML-каталоге, и в API.
4. **Хранимая XSS.** `html.escape(note)` при выводе заметки.
5. **Обход каталога.** Имя файла проверяется по списку допустимых символов, и
   после сборки путь сверяется с каталогом `data` через `os.path.realpath`.
   Одной проверки «нет ли `..`» мало: `/etc/passwd` проходит её без единой
   точки, потому что `os.path.join` с абсолютным путём отбрасывает первый довод.

Что в решении **намеренно не чинится**: доступ к чужому заказу, проверка роли,
знак количества, заголовки безопасности и флаги cookie. Пробы их не касаются, и
это отдельный разговор — ровно тот, ради которого написана тема `dast-limits`.

## Как проверить, что починка не сломала лавку

`check_fix.py` считает зачётом только два зелёных сразу. Это не формальность:
самый простой способ закрыть все шесть проб — убрать поиск, каталог и заметку.
Функциональные проверки такой «фикс» ловят.
