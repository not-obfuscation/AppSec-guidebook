# Лаба zap-scanning: разверни, просканируй, разбери отчёт

Уязвимое приложение «Лавка» на стандартной библиотеке Python. Слушает только
`127.0.0.1:8081` и никуда наружу не ходит. Что именно в него подставлено — не
сказано: это и есть задача.

Рядом лежат четыре сохранённых прогона ZAP 2.17.0. Их достаточно, чтобы пройти
лабу целиком без установки ZAP; свой прогон — для тех, кто его поставил.

## Файлы

| файл | что это |
|---|---|
| `stand/` | приложение, спецификация OpenAPI и три файла данных |
| `stand.sh` | `start`, `stop`, `reset` |
| `plans/passive.yaml` | план ZAP: паук плюс пассивные правила |
| `plans/active.yaml` | то же плюс активное сканирование |
| `plans/auth-good.yaml` | прогон под входом: `/logout` исключён, верификация задана |
| `plans/api.yaml` | импорт спецификации вместо паука |
| `runs/*.txt` | сохранённые отчёты этих четырёх прогонов, 2026-08-25 |
| `answers.csv` | таблица на семнадцать строк — её и надо заполнить |
| `key.yaml` | разметка; открывается после своей попытки |
| `check.py` | сверка `answers.csv` с разметкой, порог 15 из 17 |
| `hack.py` | шесть проб: полезные нагрузки, которыми ZAP нашёл дефекты |
| `tests.py` | семь функциональных проверок: лавка работает |
| `check_fix.py` | задача «почини»: `hack.py` и `tests.py` зелёные разом |
| `solution/app.py` | эталон починки |
| `hint.md` | одна подсказка |
| `solution.md` | разбор: что подставлено, что сканер нашёл и чего не нашёл |

## Запуск

```text
cd pilot/lab/zap-scanning
./stand.sh start                    # http://127.0.0.1:8081/
../../../.venv-tools/bin/python check.py
```

**Сброс:** `./stand.sh reset` — стенд поднимается заново, журнал и сохранённые
заметки забываются. **Удаление:** снести каталог; ничего вне него лаба не
создаёт.

Свой прогон ZAP, если он поставлен, — из этого же каталога:

```text
/путь/к/ZAP/zap.sh -cmd -dir ./zaphome \
    -config callhome.tel.enabled=false \
    -config start.checkForUpdates=0 \
    -autorun "$PWD/plans/active.yaml"
```

Числа в `runs/` сняты на ZAP 2.17.0. Свой прогон на другой версии даст другой
список — это нормально и само по себе находка про воспроизводимость.

## Что сделать

**Задача чтения.** Заполнить в `answers.csv` две колонки для каждой из
семнадцати строк отчёта `runs/auth-good.txt`.

* **вердикт** — одна буква: `и` истинная находка, `л` ложное срабатывание,
  `д` дубль (адрес не указывает на место дефекта, а сам дефект уже показан в
  таблице по верному адресу), `н` не дефект (сообщение информационное).
* **признак** — одна фраза о том, по чему это видно. Проверялка её не
  сверяет, но без неё строка не засчитывается: вердикт без признака —
  угадывание.

**Цель одной фразой:** получить от `check.py` совпадение не ниже, чем на
пятнадцати строках из семнадцати.

## Отдельная задача «почини»

Закрыть шесть проб `hack.py`, не сломав ни одной проверки `tests.py`.

```text
./stand.sh reset
../../../.venv-tools/bin/python check_fix.py
```

**Критерий:** `check_fix.py` печатает «зачтено». Одно без другого не считается:
приложение, у которого выключен поиск, ни одной пробы не проходит — и семь
функциональных проверок падают.

## Границы

Стенд уязвим намеренно. Он слушает петлю, не ходит в сеть и не читает ничего
вне своего каталога. Сканировать им можно только его же: активное сканирование
чужого узла — действие в чужой инфраструктуре, а не проба пера.
