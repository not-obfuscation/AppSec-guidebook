# Решение

Правок две, и порознь они не работают.

**1. Артефакт объявляется на стороне потребителя.** У job `test` в
`pipeline.yml` было `uses: []`:

```text
- name: test
  stage: test
  needs: build
  uses: [out/app.txt]
```

`needs` говорит «после build», и только. Доставку задаёт отдельное объявление:
в GitHub Actions это шаг `actions/download-artifact`, в GitLab CI —
`dependencies` или `needs: [{job: build, artifacts: true}]`. Порядок и передача
состояния — две разные вещи, и вторая по умолчанию выключена.

**2. Тест, который ничего не нашёл, обязан краснеть.** В `src/test_app.py`
стояло `return 0` на ветке «артефакта нет»:

```text
    if not art.exists():
        print("тест: артефакта нет — проверять нечего")
        return 1
```

Это общее правило, а не деталь этой лабы: проверка, не нашедшая объекта
проверки, отдаёт «неизвестно», а не «чисто». Код возврата 0 при отсутствии
объекта — самый дешёвый способ получить зелёный конвейер, который ничего не
гарантирует.

**Почему одной правки мало.** Оставьте только первую — тест начнёт проверять
артефакт, но следующая же ошибка в описании конвейера снова тихо отключит
проверку, и никто не заметит. Оставьте только вторую — конвейер покраснеет
сразу и на исправной сборке, потому что артефакта в рабочем каталоге нет.
Первая правка даёт тесту объект, вторая — не даёт потерять его молча.

Проверяется двумя прогонами: на исправной сборке конвейер зелёный и тест
печатает, что проверил артефакт; на испорченной — красный.
