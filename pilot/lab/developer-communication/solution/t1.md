# Т-1: страница ошибки возвращает значение параметра без экранирования

Отчёт, из которого взята находка: `reports/zap-40026.txt`.

## Вердикт

дефект

## Шаги

```text
GET /files?name=<script>alert(1)</script>
```

## Ожидалось

Ответ 404 или 400 со страницей «файл не найден» без содержимого параметра.

## Получено

Ответ 500, и значение параметра возвращается в разметке как есть:

```text
<pre>FileNotFoundError: [Errno 2] No such file or directory:
'/…/stand/data/<script>alert(1)</script>'</pre>
```

В теле ответа стоят настоящие теги `<script>`, а не их экранированная запись.
Заодно наружу уходит абсолютный путь к каталогу приложения.

## Влияние

Разметка из параметра выполняется в браузере посетителя, который открыл
присланную ссылку. Класс — `CWE-79`; протечка пути — `CWE-209`. Вход для этого
не нужен: ручка отвечает без сессии.

## Предложение

Обработчик исключений в `stand/app.py` печатает `type(exc).__name__` и текст
исключения. Текст исключения содержит данные запроса, поэтому:

* экранировать текст перед подстановкой (`html.escape`);
* лучше — не печатать текст исключения на странице вовсе, а писать в журнал и
  отдавать посетителю страницу без подробностей.

Одно место, одна правка.

## Срок

Актив доступен извне, эксплуатация автоматизируется, контроль над сессией
посетителя — частичный: по таблице сроков это 14 дней. Раньше — если ручка
попадёт в поисковую выдачу.
