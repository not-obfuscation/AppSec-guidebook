# Лаба developer-communication: заявка, по которой чинят

Три находки на одном стенде и три заявки к ним. Стенд слушает только
`127.0.0.1:8082` и наружу не ходит.

Задача не в том, чтобы найти дефекты: два из трёх уже найдены сканером, и его
отчёт лежит рядом. Задача — написать про них так, чтобы починили.

## Файлы

| файл | что это |
|---|---|
| `stand/` | приложение и один файл данных |
| `stand.sh` | `start`, `stop`, `reset` |
| `reports/active.txt` | отчёт активного прогона ZAP 2.17.0 по этому стенду |
| `reports/zap-40026.txt` | одна строка отчёта — находка для заявки Т-1 |
| `reports/zap-10027.txt` | одна строка отчёта — находка для заявки Т-2 |
| `reports/nothing-found.txt` | почему для Т-3 строки отчёта нет |
| `tickets/t1.md`, `t2.md`, `t3.md` | три заявки — их и надо заполнить |
| `key.yaml` | ключ проверки; открывается после своей попытки |
| `check.py` | повторяет шаги из заявок на стенде |
| `hint.md` | одна подсказка |
| `solution/` | эталонные заявки |
| `solution.md` | разбор: что подставлено и почему заявки такие |

## Запуск

```text
cd pilot/lab/developer-communication
./stand.sh start                    # http://127.0.0.1:8082/
../../../.venv-tools/bin/python check.py
```

**Сброс:** `./stand.sh reset` — стенд поднимается заново, сессии забываются.
**Удаление:** снести каталог; ничего вне него лаба не создаёт.

## Что сделать

Заполнить в каждой заявке семь разделов. Шесть из них — про содержание, и
проверяет их человек. Седьмой, «Шаги», читает машина.

* **Вердикт** — `дефект` или `не дефект`. Одна из трёх находок дефектом не
  является, и назвать её так — часть работы, а не отказ от неё.
* **Шаги** — ограждённый листинг, по строке на запрос:
  `METHOD /путь [тело для POST]`. Полезная нагрузка пишется целиком.
* **Ожидалось**, **Получено** — что должно было произойти и что произошло;
  во втором — фрагмент ответа, а не пересказ.
* **Влияние** — что из этого следует для пользователя или для данных.
* **Предложение** — одно место в коде.
* **Срок** — к какому числу и почему именно к нему.

**Цель одной фразой:** получить от `check.py` слово «зачтено».

`check.py` берёт строки раздела «Шаги», повторяет их одной сессией на стенде и
смотрит, есть ли в ответе последнего запроса признак из ключа. То есть заявка
обязана воспроизводиться **по собственному тексту** — без ваших пояснений и
без вашего браузера. Это и есть наблюдаемый критерий: заявка, которую нельзя
повторить, читая только её, до починки не доходит.

## Границы

Стенд уязвим намеренно. Он слушает петлю, не ходит в сеть и не читает ничего
вне своего каталога. Отчёт в `reports/` снят на этом же стенде: свой прогон
ZAP не нужен, но и не помешает.

Три раздела из семи — влияние, предложение и срок — машина не проверяет.
Сверьте их с эталоном в `solution/` после того, как получите «зачтено».
