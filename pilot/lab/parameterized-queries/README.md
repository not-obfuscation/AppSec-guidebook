# Лаба: параметризованные запросы и границы применимости

Формат Secure Code Game: чините `code.py`, пока `hack.py` и `tests.py`
не станут зелёными одновременно.

**Цель одной фразой:** добиться, чтобы `hack.py` вышел с кодом 0, а
`tests.py` продолжил выходить с кодом 0.

Всё исполняется локально, только модулем `sqlite3` из стандартной
библиотеки, без сети и без Docker. База живёт в памяти процесса.

Тема лабы — не «параметризуй всё», а граница применимости: значение одной
категории уже передано параметром правильно, а список id переменной длины
собран в запрос склейкой. Починка — сгенерировать заполнитель на каждый
элемент списка, а не вернуться к склейке под предлогом «список параметром
не передать».

## Запуск

Нужен Python 3.9 или новее. Проверено на 3.14.7.

```bash
cd pilot/lab/parameterized-queries
python3 tests.py   # ожидается: упало 0, код возврата 0
python3 hack.py    # ожидается: ЭКСПЛОЙТ СРАБОТАЛ, код возврата 1
```

Против образцового решения:

```bash
LAB_TARGET=solution.py python3 hack.py
LAB_TARGET=solution.py python3 tests.py
```

## Что проверяет эксплойт

| Опыт | Приём | Что получает атакующий |
|---|---|---|
| 1 | строка в списке id рвёт `IN (...)` | невыпущенные товары в выдаче |
| 2 | контроль: обычная выборка по id | доступ должен остаться |
| 3 | контроль: выборка по категории | параметр не тронут, работает |

## Файлы

| Файл | Что это |
|---|---|
| `code.py` | То, что чините |
| `hack.py` | Эксплойт; зелёный, когда список отвергнут как данные |
| `tests.py` | Функциональность; должна остаться зелёной |
| `hint.md` | Одна подсказка |
| `solution.py` | Образцовое решение |
| `labtarget.py` | Загрузчик проверяемого модуля |

## Сброс

Состояние держится в памяти процесса. Чтобы вернуть исходный `code.py`,
восстановите его из репозитория гайдбука.

## Удаление

```bash
rm -rf pilot/lab/parameterized-queries
```

Ничего вне этого каталога лаба не создаёт и не меняет.
