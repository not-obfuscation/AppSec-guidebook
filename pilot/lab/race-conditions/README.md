# Лаба race-conditions: проверка отдельно от записи

Кошелёк выдаёт деньги со счёта и применяет одноразовый промокод. Оба
обработчика читают состояние, принимают решение и записывают его — тремя
разными запросами к базе. Между чтением и записью лежит окно, в которое
попадают одновременные запросы: остаток проверен всеми, списан каждым.

## Файлы

| файл | что это |
|---|---|
| `code.py` | уязвимый кошелёк: чтение, решение и запись — разные запросы |
| `solution.py` | образец починки: условный UPDATE и уникальный ключ в схеме |
| `hack.py` | эксплойт: 20 потоков, 30 прогонов; возврат 0 — почин, 1 — уязвимо |
| `tests.py` | функциональность кошелька: должна остаться зелёной |
| `sandbox.py` | база во временном каталоге, счёт 100 и код `SALE` |
| `labtarget.py` | загрузка проверяемого модуля (`LAB_TARGET=solution.py`) |
| `hint.md` | одна подсказка |

## Как запускать

```text
cd pilot/lab/race-conditions
../../../.venv-tools/bin/python hack.py      # против code.py: 2 из 2 опытов
../../../.venv-tools/bin/python tests.py     # функциональность: 0 упало
LAB_TARGET=solution.py ../../../.venv-tools/bin/python hack.py    # 0 опытов
LAB_TARGET=solution.py ../../../.venv-tools/bin/python tests.py   # 0 упало
```

Числа в отчёте эксплойта плавают от прогона к прогону: гонка вероятностна.
На уязвимом коде перерасход появляется в 15–20 прогонах из 30, а число выдач
со счёта в 100 доходит до 8–15 при 20 одновременных запросах. Важен не
конкретный счёт, а то, что предел снесён хотя бы раз.

## Цель одной фразой

Добиться, чтобы `hack.py` вышел с кодом 0 (оба предела удержаны во всех
прогонах), а `tests.py` продолжил выходить с кодом 0.

## Задача «почини»

Закройте два обхода в `code.py`: снятие сверх остатка двадцатью одновременными
запросами и применение одноразового кода больше одного раза. Семь проверок
функциональности должны остаться зелёными — снятие в пределах остатка
проходит, снятие сверх остатка отвергается, второе применение кода
отвергается.

## Правило SAST

`pilot/semgrep/read-modify-write-no-lock.yaml` ловит запись значения,
посчитанного в приложении после чтения той же строки: на `code.py` одна
находка, на `solution.py` — ноль.
Сверка: `.venv-tools/bin/python pilot/semgrep/check.py read-modify-write`.

Всё исполняется локально, к сети не обращается и применимо только к этой лабе.

## Сброс

База ставится во временный каталог системы при каждом запуске, между
запусками ничего не остаётся. Чтобы вернуть исходный `code.py`,
восстановите его из репозитория гайдбука.

## Удаление

```bash
rm -rf pilot/lab/race-conditions
```

Вне этого каталога лаба создаёт только базу во временном каталоге
системы (префикс `lab-race-`); она остаётся там до очистки системой.
