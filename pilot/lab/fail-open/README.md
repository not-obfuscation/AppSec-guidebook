# Лаба fail-open: отказ проверки, прочитанный как разрешение

Внутренний интерфейс спрашивает право на действие у службы прав и считает
попытки входа во внешнем хранилище счётчиков. Пока обе зависимости живы,
приложение ведёт себя правильно, и функциональные проверки это подтверждают.
Ломается оно на пути ошибки: у проверки три исхода, а веток в коде две.

## Файлы

| файл | что это |
|---|---|
| `code.py` | уязвимое приложение: три решения при отказе, все три — пропуск |
| `solution.py` | образец починки: третий исход получает свою ветку и 503 |
| `hack.py` | эксплойт: три опыта и контрольный; возврат 0 — почин, 1 — уязвимо |
| `tests.py` | функциональность прав и ограничителя: должна остаться зелёной |
| `sandbox.py` | служба прав и хранилище счётчиков, всё в памяти |
| `labtarget.py` | загрузка проверяемого модуля (`LAB_TARGET=solution.py`) |
| `hint.md` | одна подсказка |

## Как запускать

```text
cd pilot/lab/fail-open
../../../.venv-tools/bin/python hack.py      # против code.py: 3 обхода открыты
../../../.venv-tools/bin/python tests.py     # функциональность: 0 упало
LAB_TARGET=solution.py ../../../.venv-tools/bin/python hack.py    # 0 обходов
LAB_TARGET=solution.py ../../../.venv-tools/bin/python tests.py   # 0 упало
```

Числа детерминированы: перебора нет, случайности нет, сети нет.

## Три опыта эксплойта

1. **Отказ службы прав.** Обычный пользователь просит все четыре
   привилегированных действия при мёртвой службе и получает четыре ответа
   с кодом 200.
2. **Отказ хранилища счётчиков.** Ограничитель частоты пропускает 60 попыток
   входа из 60 при лимите в 5 — то есть перестаёт существовать.
3. **Ответ без решения.** Служба жива, но решения не приняла: в ответе есть
   `error` и нет `allow`. Разбор подставляет разрешение по умолчанию.

Контрольный опыт проверяет, что при живых зависимостях права работают:
админу 200, обычному пользователю 403 на привилегированное и 200 на чтение,
а ограничитель пропускает ровно пять попыток.

## Цель одной фразой

Добиться, чтобы `hack.py` вышел с кодом 0 (все три обхода закрыты, контрольный
опыт цел), а `tests.py` продолжил выходить с кодом 0.

## Задача «почини»

Разведите три исхода проверки и не сломайте законную работу: шесть проверок
функциональности должны остаться зелёными. Отказ зависимости — не разрешение
и не запрет, у него свой ответ. Ограничитель частоты при отказе хранилища
обязан остаться ограничителем, а не исчезнуть.

## Правило SAST

`pilot/semgrep/authz-fail-open.yaml` ловит два признака блока 5 темы: широкий
перехват, возвращающий разрешение, и умолчание разбора, подставляющее
разрешение вместо отсутствующего решения. На `code.py` две находки, на
`solution.py` — ноль.
Сверка: `.venv-tools/bin/python pilot/semgrep/check.py authz-fail-open`.

Что правило пропустит: третий дефект `code.py` — перехват в `authorize`,
возвращающий не `True`, а строку ответа `"200 <action>"`. Форма возврата
у обработчика своя в каждом проекте, и правило, которое ловит любой возврат
из широкого перехвата, даёт больше шума, чем находок. Этот случай остаётся
за глазами ревьюера, и потому чеклист темы спрашивает про исходы, а не про
конструкцию.

Всё исполняется локально, к сети не обращается и применимо только к этой лабе.
