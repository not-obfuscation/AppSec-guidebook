# Матрица нормативных чисел

Единый реестр числовых рекомендаций корпуса: какая тема владеет числом и
где оно ещё упоминается. Назначение: при аудите и правках сверять темы
с этой таблицей, а не попарно друг с другом. Построена аудитом
2026-08-30 (`journal/AUDIT-2026.md`, слой 5), противоречий в корпусе
тогда не найдено. Правило: меняешь число в теме-владельце — проверь
все строки таблицы по этой величине и обнови саму таблицу.

| Величина | Владелец | Значение |
|---|---|---|
| Энтропия идентификатора сессии | `secure-random` | ≥ 128 бит (ASVS 7.2.3); расхождение с Cheat Sheet (≥ 64) оговорено в `sessions-vs-tokens` |
| Порог «быстрый хеш от секрета» | `password-storage` | ≥ 112 бит (ASVS 6.5.2); зазор 112 vs 128 разобран в самой теме |
| Параметры KDF | `password-storage` | Argon2id t=2, m≥19456, p=1; scrypt N≥2¹⁷, r=8, p=1; bcrypt cost≥10, вход ≤72 байт; PBKDF2-HMAC-SHA-256 ≥600 000 |
| Длина пароля | `password-storage` | минимум 8 (ASVS 6.2.1, NIST 800-63b), рекомендовано 15, приём до 64 (ASVS 6.2.9) |
| Таймауты сессии | `session-fixation` | бездействие 2–5 мин (высокий риск) / 15–30 мин, абсолютный 4–8 ч |
| Блокировка при переборе | `brute-force-defense` | 5–10 попыток, выдержка 5–30 мин |
| Ключ HS256 | `jwt-basics` | размер ≥ выхода хеша (256 бит), энтропия ≥ 160 бит |
| Усечение метки HMAC | `rfc2104-hmac` (RFC 2104 § 5; темы-владельца нет — число живёт в аннотации этого источника в `hmac-vs-signature`) | не короче половины выхода и не короче 80 бит |
| TLS | `weak-algorithms` | 1.3 по умолчанию, 1.2 при нужде, старше — отключено |
| HSTS max-age | `security-headers` | ≥ 1 года (ASVS 3.4.1); 63072000 — пример для preload-листа |
| SameSite по умолчанию | `csrf-mechanics` | Lax, окно ~2 мин после выставления (замер 135 с) |
| `SameSite=None` | `cookies` | требует `Secure` |
| Срок persistent-cookie | `persistent-login-tokens` | 30 дней (исправлено), год — в уязвимом примере |
| Access-Control-Max-Age | `cors` | умолчание 5 с, пример 86400 |
| IMDSv2 | `cloud-metadata-ssrf` | TTL токена ≤ 21600 с, hop-limit 1 (2 — в уязвимом примере) |
| SLA на устранение | `sla-and-backlog` | 3 / 14 / 60 дней |
| EPSS | `cve-cvss` | вероятность 0–1, горизонт 30 дней; балл пересчитывается моделью ежедневно |

Известные пробелы (чисел в корпусе нет сознательно или не заведены):
норматив TTL access-токена в минутах (в примерах показан часовой срок —
`exp: issued + 3600` и `expiresIn: "1h"` в `jwt-basics`; качественная норма
«минуты, а не часы» стоит в `token-lifetime-revocation`), лимиты глубины
GraphQL, лимиты размера загружаемых файлов, пороги памяти для DoS.
