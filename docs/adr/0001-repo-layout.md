# ADR 0001: Структура репозитория

- Статус: accepted (2026-08-30)
- Контекст и решения подробно: `PLAN-REORG.md`

## Context

В корне репозитория накопилось ~46 markdown-файлов: действующие нормы
(PLAYBOOK, SCHEMA, STYLE, SCOPE) лежат вперемешку со снимками завершённых
миссий (WRITE-*, STAGE*-*, INTROS-* и т.п.). Точку входа найти трудно,
живые документы не отличить от архивных. Конвейер (`tools/`) читает
корневые yaml-реестры и `content/` по жёстко заданным путям; из корневых
md кодом открывается только генерируемый `GLOSSARY.md`.

## Decision

1. В корне остаются только «контрактные» файлы: README, Makefile,
   mkdocs.yml, .gitignore, HANDOFF.md, действующие нормы
   (PLAYBOOK/SCOPE/SCHEMA/STYLE), yaml-реестры.
2. Снимки завершённых миссий переезжают в `journal/` с сохранением
   исторических имён. Живые отчёты о состоянии — в `docs/reports/`.
   Решения — в `docs/adr/NNNN-*.md` (формат Нюгарда, нумерация
   монотонная, не переиспользуется).
3. Не делаем: переименование `content/stage-N/`, переезд корневых yaml,
   перекройку контента, переписывание git-истории (filter-repo).
   Публичные URL сайта не меняются.
4. Переезды — только `git mv`, отдельными коммитами от правок
   содержимого, каждый коммит зелёный (`make check`).
5. Все пути в инструментах сводятся в единый модуль `tools/paths.py`;
   путь к внешнему учебному плану — через переменную окружения
   `APPSEC_PLAN_PATH`.

## Consequences

Плюсы: корень читается за экран; история файлов сохраняется
(`git log --follow`); конвейер перестаёт зависеть от cwd и абсолютных
путей. Минусы: HANDOFF.md и docstring'и требуют разовой правки ссылок;
исторические упоминания старых путей в `journal/` и `.smgr/` сознательно
остаются как есть (это снимки прошлого).
